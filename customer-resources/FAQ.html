Hosting, data and recovery

托管、数据与恢复

Is this a production deployment, and where does it run?这是正式的生产部署吗？运行在哪里？

Yes, since 30 July 2026. pwestudio.online runs from one host on Oracle Cloud in the Melbourne region (ap-melbourne-1). It ran on AWS in Sydney until 17 September 2026 and moved on that day. Requests reach the host through Cloudflare, which carries the public certificate; a web server on the host receives them over TLS and passes them to the application. HTTP redirects to HTTPS and HSTS is set for one year. The application listens only on the host’s loopback interface and is reached through that edge.

是，自 2026 年 7 月 30 日起。pwestudio.online 由位于 Oracle Cloud 墨尔本区域（ap-melbourne-1）的一台主机提供服务。2026 年 9 月 17 日之前它运行在 AWS 悉尼，当天完成迁移。请求经 Cloudflare 到达主机，公开证书由 Cloudflare 提供；主机上的 Web 服务器以 TLS 接收请求，再转给应用。HTTP 跳转至 HTTPS，HSTS 有效期一年。应用只监听主机本地回环地址，对外一律经该边缘转发。

Where is our data stored?我们的数据存放在哪里？

In the Melbourne region (ap-melbourne-1), on the host itself: PostgreSQL 16 runs beside the application, and media files sit on the host’s own storage. The runtime connects with a restricted database role; the owner role is used only for schema migrations at start-up. No managed database, object-storage or mail service holds the live data. The one copy that leaves the host is the encrypted backup described in the next answer.

在墨尔本区域（ap-melbourne-1），且就在这台主机上：PostgreSQL 16 与应用同机运行，媒体文件存放在主机自己的存储上。运行时使用受限数据库角色连接；只有启动时的结构迁移才使用 owner 角色。没有任何托管数据库、对象存储或邮件服务保存线上数据。唯一离开主机的副本，是下一条回答里说的加密备份。

Are there backups, and has a restore actually been tested?有备份吗？恢复真的演练过吗？

Yes to both. The database is backed up every night at about 03:15 Melbourne time; uploaded media and the rest of the host’s files are backed up on the first of each month. Each backup is encrypted on the host before it leaves, then stored off the host in Cloudflare’s object storage; Cloudflare does not hold the key. A restore was rehearsed on 17 September 2026: a database backup was fetched from that off-site copy, decrypted and restored into a separate database, and its tables and tenants matched production. Three limits are worth stating plainly. Media is copied monthly, not nightly, so an upload can be up to a month old before it has an off-site copy. Cloudflare chooses where the encrypted copy is stored and we have not pinned it to Australia. And there is no automated alert if a backup run fails, so backup output is checked as an operator task rather than by monitoring.

两者都有。数据库每晚约 03:15（墨尔本时间）备份一次；上传的媒体和主机上的其余文件每月 1 日备份一次。每份备份先在主机上加密，再离开主机，存放在 Cloudflare 的对象存储里；Cloudflare 不持有密钥。恢复在 2026 年 9 月 17 日演练过：从这份异地副本取回一份数据库备份，解密后恢复进一个独立的数据库，表和租户与生产一致。有三点需要明说：媒体是每月备份，不是每晚，所以一次上传最长可能一个月后才有异地副本；加密副本存放在哪里由 Cloudflare 决定，我们没有把它限定在澳大利亚境内；备份失败没有自动告警，因此备份结果依赖运维人工检查，而非监控系统。

Is there monitoring and an availability commitment?有监控和可用性承诺吗？

Not yet. Uptime monitoring, backup-failure alerting, an on-call path and a contractual availability target are not in place. Health and version can be checked on demand, and a branded maintenance page is served if the application is briefly unavailable during an upgrade, but that is not the same as a monitored service with an SLA. Any availability target has to be written into a signed order form.

尚未完成。运行时监控、备份失败告警、值班响应路径与合同化可用性目标均未建立。可以按需查看健康状态与版本，升级期间应用短暂不可用时会展示品牌化维护页面，但这不等于「有监控、有 SLA 的服务」。任何可用性目标都必须写入已签署的订单。

Does PWE Studio require multi-factor authentication?PWE Studio 有多因素认证吗？

No, and this is now an open gap on a live service rather than a pre-launch to-do. Role separation, PBKDF2-HMAC-SHA256 password hashing with 600,000 iterations, HttpOnly session cookies, rate limiting on student access codes and audit logging are all in place. Multi-factor authentication for privileged accounts is not, and remains our highest-priority security item. Until it ships, keep privileged logins individual, use a password manager, and tell us immediately if you suspect an account is compromised.

没有。这已经是「已上线服务上的公开缺口」，不再是上线前的待办事项。角色分离、PBKDF2-HMAC-SHA256（600,000 次迭代）密码散列、HttpOnly 会话 Cookie、学员访问码速率限制与审计日志均已具备；特权账号的多因素认证尚未具备，是我们优先级最高的安全事项。在其上线前，请保持特权账号一人一号、使用密码管理器，并在怀疑账号被盗时立即通知我们。

Using the product

产品使用

What is the difference between Studio Admin and CMS?Studio Admin 与 CMS 有什么区别？

Studio Admin is the owner’s website and brand workspace. CMS is the daily operations workspace for enquiries, students, rosters, attendance, credits, artwork and reports. They share identity and stable links, while responsibilities and permissions remain separate.

Studio Admin 是主理人的网站与品牌工作台。CMS 是日常运营工作台，处理咨询、学员、排课、签到、课时、作品与报表。两者共用品牌识别与稳定入口，但职责与权限彼此独立。

Can families sign in?家长可以登录吗？

A family unlocks one student’s private area with the student name, the registered mobile number and a six-digit code issued by the studio. It shows that student’s credit balance, next class, attendance and portfolio, and nothing belonging to another student. Attempts are rate-limited and temporarily locked after repeated failures. Multi-child account aggregation is not part of v__APP_VERSION__.

家长使用学员姓名、登记手机号，以及工作室发放的六位访问码，解锁该名学员的私人区域。可见内容为该学员的课时余额、下次课、出勤与作品集，不含其他学员的任何信息。尝试次数受限，多次失败后会临时锁定。v__APP_VERSION__ 不包含多子女账户汇总。

Does PWE Studio send SMS or email automatically?PWE Studio 会自动发送短信或邮件吗？

Most operator actions open your own Mail or Messages application with prepared text, and you decide whether to send. PWE Studio also has a logged SMTP path for configured transactional events, but it sends externally only when the deployment supplies and operates its own sending account and domain. No managed sending domain or SMS provider transport is included by default.

大多数运营操作只会打开设备自带的邮件或信息应用并预填文本，由你决定是否发送。PWE Studio 也具备带日志的 SMTP 事务邮件路径，但只有部署方提供并运维自己的发信账号与域名时才会对外发送。标准服务不默认包含托管发信域名或短信服务商传输。

Are online payments included?包含在线支付吗？

No. Staff can record purchases, invoices, payments, refunds and credit adjustments, and every action is audited, but PWE Studio does not capture cards or move money. Automatic merchant/bank settlement reconciliation is deferred. The optional Xero add-on pushes recorded documents one way; it is not a payment processor. Do not upload payment-card numbers into any field.

不包含。工作人员可以记录购买、发票、收款、退款与课时调整，且每一项都会写入审计记录，但 PWE Studio 不采集银行卡，也不划转资金。商户/银行结算的自动对账属于延后项；可选 Xero 加购只会单向推送已记录单据，不是支付处理器。请勿在任何字段中上传银行卡号。

Can any CSV or Excel file be imported?任何 CSV 或 Excel 文件都能导入吗？

We provide standard templates and a migration assessment. Arbitrary files usually need field mapping and may need paid clean-up. A production import only proceeds after an exceptions report, your written approval, a checkpoint, a rehearsal and a reconciliation.

我们提供标准模版与迁移评估。任意来源的文件通常需要字段映射，可能需要付费清洗。正式导入必须先完成异常报告、你的书面确认、检查点、演练与对账，才会执行。

What is in the ICS calendar export?ICS 日历导出包含什么？

There are two distinct exports. The weekly schedule contains active recurring classes, course details and location in the studio’s local time, and excludes student and guardian identities. The daily roster may contain student names because it is an operational attendance file; it is restricted to staff with data-export permission, is marked private before download and never contains guardian names.

系统提供两种不同的导出。周课表按工作室当地时间包含固定循环课程、课程信息与地点，不含学员或监护人身份。日名单属于签到运营文件，可能包含学员姓名；仅拥有数据导出权限的员工可下载，下载前明确标记为私密文件，且从不包含监护人姓名。

How are multiple campuses handled?多校区如何处理？

In v__APP_VERSION__ one campus is one tenant and one subscription. This keeps student records, staff membership, schedules, brand, plan and — importantly — backup, export, deletion and incident scope independent per campus. A future organisation layer may aggregate isolated campus tenants for reporting without merging their operational data.

v__APP_VERSION__ 中，一个校区即一个租户、一份订阅。这样可以让学员记录、员工成员、排课、品牌、套餐，以及——同样重要的——备份、导出、删除与事故范围，按校区彼此独立。未来的组织层可能为报表聚合多个独立校区租户，但不会合并其运营数据。

Are custom domains and third-party integrations live?自定义域名与第三方集成上线了吗？

Studio pages remain under the platform domain; per-studio custom domains, Stripe, provider calendar APIs and SMS provider transport are deferred unless a signed order includes implementation and acceptance. Xero is different: it is a paid Beta add-on with OAuth, reviewed mappings, a Demo Company trial, a persistent queue and gated one-way push for issued invoices, credit notes and recorded payments. It never imports or applies edits from Xero, and pushing stays off until every gate passes.

工作室页面仍托管在平台域名下；按工作室的自定义域名、Stripe、日历服务商 API 与短信服务商传输均属延后项，除非已签署订单明确包含实施与验收。Xero 不同：它是付费 Beta 加购，具备 OAuth、复核后的科目映射、Demo Company 试跑、持久队列，以及对已开具发票、贷记单与已记录收款的门控单向推送。系统不会从 Xero 导入或应用修改，所有门槛通过前推送始终关闭。

Getting help. Read the support policy, then use Support & Feedback on the product home. Include your studio name, the affected role, the time and the page. Never put passwords, student access codes, payment details or sensitive student information in a first message.

需要帮助。请先阅读支持政策，再使用产品首页的「支持与反馈」。请提供工作室名称、涉及角色、时间与页面。首次沟通中请勿包含密码、学员访问码、付款信息或敏感学员资料。
