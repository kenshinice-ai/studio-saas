## 0. 一分钟背景

StudioSaaS 是多租户 SaaS，四个界面：

```
Super Admin  (super-admin.html)              平台方开租户 / 套餐 / 生命周期
Studio Admin (backend/frontend/studio-admin.html)  租户 Owner 管品牌·配色·门户·报名表
CMS          (legacy-root/src/cms-app.jsx)   店员管学员·排课·签到·课时·作品
Portal       (tenant-template/index.html)    访客报名 + 学员凭访问码自助查询
Register     (tenant-template/register.html) 独立报名页
```

**关键约束**：`tenants/<slug>/` 是**生成目录**，由 `backend/studiosaas/workspaces.py` 从
`tenant-template/` 渲染。改完模板必须跑：

```bash
.venv/bin/python backend/scripts/regenerate_tenant_workspaces.py
```

## 2. 待办清单（下一个会话要做的）

> 依据是 2026-07-26 的实测排查，每条都有证据。**优先级从上到下。**

### 批次 1 · 两个确定 bug（改动极小）

**1-1 联系信息在切换语言后不重渲染** ⭐ 真 bug
`tenant-template/index.html` 的 `setLang()` 重渲染了 programs / gallery / faq /
brandCopy / about，**漏了 `renderContactRows`**：

```js
// 约 702 行
if(state.programs) renderPrograms(state.programs);
if(state.gallery)  renderGallery(state.gallery);
if(state.faq)      renderFaq(state.faq);
if(state.brand && state.brand.name){ applyBrandCopy(state.brand); renderAbout(state.brand); }
// ← 少 renderContactRows(state.brand)
```
实测：英文模式下「地址 / 邮箱 / 电话」三处仍是中文。

**1-2 `modes` 缺失时谎报「仅提供明亮模式」** ⭐ 我引入的回归
`backend/frontend/studio-admin.html` `renderStylePresetGrid()`：
```js
const modes = selected.modes && selected.modes.length ? selected.modes : ['light'];
```
旧/缓存数据没有 `modes` → 降级 `['light']` → UI 说
「Xxx 仅提供明亮模式——它的强调色在另一种底色上无法达到可读对比度」。
**这句话是编的。** 要区分「数据缺失」（显示加载中/重试）和「真的只有一种模式」。

### 批次 2 · 色系命名没有露出 ⭐ 用户点名

**2-1 `label_zh` 全链路未使用**
8 个中文名（陶土工坊 / 复古印刷 / …）在 `presets.py` 里有，
但 `renderStylePresetGrid()` 只写 `style.label`，中文界面下全是英文。

**2-2 主题描述退化成英文小写碎片**
我的生成器把 `mood` 当 `description` 输出：
```
warm, tactile, gallery / editorial, cultured / timeless, content-led / ...
```
旧版是完整句子且有中文翻译。**8 条全部不在 `admin-i18n.js`**（grep 命中 0）。
要补：完整中英文描述各 8 条，写进 `presets.py` + `admin-i18n.js`。

### 批次 3 · Studio Admin 排版（纯 CSS）

**3-1 步骤 02 两控件不对齐** ⭐ 实测
```
主题 select      x=94  y=1169  w=214  h=46
明暗模式 select   x=322 y=1149  w=380  h=42
```
宽度差 166px、基线差 20px、高度差 4px；说明文字也错开（y=1222 vs 1196）。

**3-2 行业卡三字母码无意义**
`key.slice(0,3)` → `DAN` / `GAM` / `GEN`，后两者视觉几乎一样。建议换图标或去掉。

**3-3 卡片高度被 `aspect-ratio: 1.18/1` 锁死**
标语 `-webkit-line-clamp: 3` 硬裁，补中文后更易截断。改成内容驱动高度。

### 批次 4 · 数据补齐

- **4-1** 行业标语 `preset.slogan` 只有英文 → 补 `slogan_zh`，卡片不再三语混排。
- **4-2** 主题下拉框按字母排序，`arcade-lime`（仅暗色的游戏主题）排在艺术租户第一位。
  改成「推荐优先 → 明暗双模 → 仅暗色」。
- **4-3** API 已返回 `harmony`，UI 未使用，可作为选择依据露出。
- **4-4** `palette-swatches` 只显示 3 色，看不到 line-strong / focus-ring / 语义三色。

### 批次 5 · 中英文链路 ⭐ 策略已定

**实测现状**：
- 中文模式下 **14 处纯英文**
- 英文模式下 **3 处中文**（即 1-1 那个 bug）

**字段分三类**：

| 类别 | 字段 | 处理 |
|---|---|---|
| **A 已双语** | hero_title/subtitle、CTA、section 标题/引导语、FAQ、registration 文案 | ✅ 保持 |
| **B 应补双语** | `welcomeMessage`、`categoryLabel`、`slogan`、`principal.title/bio/quote`、`registrationProfile.title`、`website_profile.*_label` | ⬜ 待做 |
| **C 不翻译** | 地址、邮箱、电话、租户名、**`programs[]`**、**`gallery[].title`** | ✅ 保持原样 |

> ### 🔴 已决策：`programs[]` 走「只存单语，前台不翻译」
>
> 课程名 / 描述 / 分类来自 CMS，是店员日常录入的运营数据，不是品牌文案。
> **不增加录入负担，不加译名字段，前台原样显示。**
> `gallery[].title`（作品标题）同理。
>
> 落地时要做的是：
> 1. 在 `docs/Glossary.md` 记下这条规则，避免以后有人"顺手"给它加翻译。
> 2. Studio Admin / CMS 的相关输入框加一句提示，说明这些内容不随界面语言切换。
> 3. **不要**把它算进"中英文混用"的 bug 清单——这是明确的产品决策。

所以批次 5 的实际工作量 = 只处理 B 类 6 个字段。

### 批次 6 · 收尾

- **6-1** 语言链路文档化：访客端 `pwe_lang_<slug>` vs 管理端
  `studiosaas_admin_language`，两套 key 是有意为之，但没写进文档；
  也没有「首次访问跟随浏览器语言」。
- **6-2** `setLang` 会改 `documentElement.lang`，但 `og:locale` / `hreflang` 没有，
  搜索引擎只看得到一种语言版本。

## 4. 踩过的坑（别再踩）

1. **不要 `git checkout` 单个文件来回滚**
   我用 `git checkout backend/studiosaas/presets.py` 想撤销一次失败的写入，
   结果把上一轮加的 `venue_noun` / `work_noun` 一起 revert 了，
   导致 `/brand` 全线 500、页面退回默认样式。排查花了不少时间。

2. **浏览器会缓存 `/v1/industry-presets`**
   用户截图里出现「Artistic Atelier」旧名字，代码里其实已经没有了——
   是**新 JS + 缓存的旧 API 响应**。排查前先确认是不是缓存。

3. **Edit 工具对 `\uXXXX` 字面量匹配不了**
   `presets.py` / `index.html` 里有 `/[㐀-鿿]/` 这类字面转义，
   Edit 的 old_string 两种形式都匹配失败。改用 Python 脚本做替换。

4. **本地测试库的副作用（已做，知悉即可）**
   - 补跑了缺失的 migration `0018_student_enrolment_date`
   - 重置过 `owner@lets-play-piano.test` / `owner@lets-paint-studio.test`
     的密码为 `admin123456`（仅本地测试库）
   - 种过又删掉 30 个 `Pager%` 测试学员

5. **`_normalize_localized_copy` 必须在读路径也调用**
   老租户存的是旧的 6 个 key，新增 section 文案读不到会退回模板兜底文案。
   已改成读时也走 normalizer 合并默认值——新增 copy 字段时记得沿用这个模式。
