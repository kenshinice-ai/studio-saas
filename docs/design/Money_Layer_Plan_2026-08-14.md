## 1 · 筛选标准与分诊（不变）

进主线要同时过三关：**普遍性** / **有重复劳动可消除** / **不引入新责任**
（不碰资金、不替客户做税务判断、不替客户申报）。

| 需求 | 结论 |
|---|---|
| 发票 / 贷记单 / 对账单 / 账龄 | **主线** |
| 在线收款（Stripe 托管页） | **主线** |
| 一对一循环课 + 补课额度 | **主线（市场准入）** |
| 家庭日历订阅 | **主线（第一波）** |
| 老师课时与应付清单 | **主线** |
| 学生成长报告 | **主线（差异化）** |
| 邮件 + 短信通知 | **主线（渠道层）** |
| 经营报表（四张） | **主线** |
| Xero 推送 | **加购（任意档）** |
| Square 通道 | **第二适配器，后置** |
| RCTI / ABA 银行文件 | 不进主线，独立版按单加购 |
| 跑批审批 / PAYG / 养老金 / STP | **永不做** |
| 多校区汇总 | 不做（已在边界文档） |

> **Sinobeats 送给我们最有价值的不是需求，是边界。** 他们主动说
> 「工资由财务做，我们只出数字和清单」，一句话把薪酬模块从会拖我们进税务
> 合规的坑，压成一个安全、可复用、两周做完的模块。这条边界写进产品定义。

## 2 · Xero 加购：三个开关，必须分开

产品方特别点了「注意开关的位置和方式」。这里是全案设计上最容易做错的一处：
**把权利、连接、推送揉成一个 toggle。** 揉在一起，三种再正常不过的情况会互相误伤。

### 三个开关

| | 开关 1 · 权利 | 开关 2 · 连接 | 开关 3 · 推送 |
|---|---|---|---|
| 回答的问题 | 这个租户**有没有买** | **连没连上**他们的 Xero | **推不推**、怎么推 |
| 谁能动 | 平台（Super Admin / 订阅流程） | 租户 **owner**（财务凭据，不给 manager/staff） | 租户 owner / manager |
| 存在哪 | `tenant_addons` | `xero_connections`（加密令牌 + org id） | `xero_sync_settings` |
| 租户侧可见性 | **只读状态徽章** | 可连、可断 | 可开、可关 |
| 独立版 | **不存在**（恒为已购） | 有 | 有 |

### 为什么必须分开 —— 用失效场景说明

- **加购到期或退订** → 只关**开关 1**。停止新推送，但连接记录、ID 映射、
  错误队列、历史全部保留，CSV 导出**永远可用**。
  （红线：不阻断财务写入、不删数据。）
- **换会计或换 Xero 组织** → 动**开关 2**，映射需重新确认，权利不受影响。
- **年末封账期间暂停推送** → 动**开关 3**，权利与连接都不动，封账结束一键恢复。

只做一个 toggle 的话，退订会顺手删掉连接，换会计会看起来像退订，封账会需要
去找平台方——每一种都是真实会发生的事。

### 开关 3 不是一个 toggle，是一道闸

**默认关，且不满足前置条件不允许打开**：

1. 科目与税率映射已填写完整；
2. 已对 **Xero 测试组织**（demo company）跑通一个完整周期；
3. 已回答**单一入口**问题 —— 租户的收款渠道（如 Square）是否已经在往 Xero
   自动同步？必须二选一：关掉对方，或本系统的收款走清算账户。

界面上是**三步向导**（连接 → 映射 → 试跑），不是设置页里的一个勾。
这三条里任何一条没过，生产账套的推送开关是灰的，鼠标悬停说明还差什么。

> 这道闸是 Sinobeats 那一单教出来的：租户的 Square 已经在同步 Xero 时，
> 我们再推一遍就是两套记录，而且是在**生产账套**里。这个坑不能让下一个
> 客户去踩，得让产品在开关那一刻就问出来。

### 权利解析（一处，别散落）

```
effective_features(tenant) =
      plan.features                     # 按档捆绑
    ∪ active_addons(tenant)             # 按租户加购，任意档
    ∪ (ALL if STUDIOSAAS_MODE=standalone)
```

**加购不能塞进 `plans.features`** —— plan features 是按档捆绑的，加购是按租户的；
混在一起，「任意档可加购」就退化成「改套餐」。

## 3 · 门禁先决条件（2026-08-14 核实）

`plans.features` 这个 jsonb **目前只用于套餐变更预览**
（`api_v1.py:1800-1806` 算 `enabled_features` / `disabled_features` 给用户看），
**没有任何一处把它当门禁执行**。真正被强制的只有数值上限
（`student_limit` / `user_limit` / `storage_limit`，全库 45 处）。

所以要落地任何分档或加购，先补**权利层**（~3 人天）：

- `tenant_addons` 表 + Super Admin 授予/撤销界面
- 统一的 `require_feature(key)` 前置钩子（服务端拦截，不只是隐藏按钮）
- 界面降级态：功能可见但标注「需加购」，不是消失
- standalone 模式恒为全开

## 4 · 套餐归档整理（不调价）

价格不动。money chain 全档可用 —— 因为把「能不能收到钱」按档切开，
会让刚刚决定服务的独立老师（Starter，`user_limit=1`）用不了产品的主干。

| | Starter $49 | Studio $99 | Growth $199 | 加购 |
|---|:--:|:--:|:--:|:--:|
| 1v1 循环课 / 补课额度 | ✅ | ✅ | ✅ | |
| 发票 / 对账单 / 账龄 | ✅ | ✅ | ✅ | |
| 在线收款（Stripe）/ 现金转账登记 | ✅ | ✅ | ✅ | |
| 家庭日历订阅 | ✅ | ✅ | ✅ | |
| 学生成长报告 | ✅ | ✅ | ✅ | |
| 邮件通知 | ✅ | ✅ | ✅ | |
| 老师课时与应付清单 | — | ✅ | ✅ | |
| 短信通道 | — | ✅ | ✅ | |
| 经营报表（四张） | — | — | ✅ | |
| **Xero 直连** | — | — | — | **任意档加购** |

分层逻辑改为**按规模与团队**，不按「能不能做生意」：

- **Starter** = 一个人的完整生意（1 用户 / 100 学员）。老师课酬对单人租户本就没有意义 ——
  这是**天然门槛**，不是人为阉割。
- **Studio** = 有团队（5 用户 / 500 学员），于是需要课酬与短信。
- **Growth** = 有人看数（20 用户 / 1000 学员），于是需要经营报表。

> **红线**：套餐可以关**功能入口**，永远不得阻断或删除**财务写入**。
> 降级后已开出的发票仍可查询、导出、打印，只是不能再用被关掉的通道开新单。
> 发票是法律文件，不是配额资源。（沿用「套餐上限管发布不管存储 / 降级绝不删数据」。）

**待定**：Xero 加购定价（建议 $19/月 或 $190/年，任意档）。机制先建，定价可后置。

## 5 · 四波交付（86 人天等效）

波次划分：**依赖顺序** + **每波都能单独上线并被用户感知**。

### 第一波 · 地基与立刻有感的价值 ｜ 18 人天

| 项 | 人天 | 说明 |
|---|:--:|---|
| 权利层（`tenant_addons` + `require_feature` + standalone 全开） | 3 | 后面所有分档与加购的前提 |
| **批次 0 · 1v1 循环课 + 补课额度 + 学期骨架** | 10 | 市场准入。补课规则同时是计费输入与课酬输入，规则不落地后面都建在沙子上 |
| **家庭 ICS 订阅** | 5 | 见下，全案投入产出比最高 |

**家庭 ICS 订阅**（决定 5，扩充范围）：

- 每个家庭一条**带令牌、可撤销**的订阅地址；可按孩子拆分
- 内容：常规课、补课、已取消的课（`STATUS:CANCELLED` 而不是悄悄消失）、
  学期假期，可选加入工作室活动与音乐会
- 调课自动同步；前台可打印二维码给家长现场扫
- 老师自己的课表订阅统一到同一套令牌模型（`calendar_export.py` 已有 90%，
  含澳洲夏令时与 RRULE）
- 隐私：令牌不可猜、可撤销、可一键全撤；事件里只放孩子名与课程，不放地址与联系方式

> **一条必须写进产品文案的诚实边界**：日历客户端按**自己的节奏**拉取
> （Google 可能隔数小时）。所以 ICS 能替代的是**例行提醒**，
> **不能替代当天的临时取消** —— 那类消息仍然必须走短信。
> 这条决定了通知层的路由规则，也决定了我们不能对外宣称「订阅之后就不用发短信了」。

### 第二波 · 钱进来 ｜ 24 人天

| 项 | 人天 |
|---|:--:|
| **批次 1 · 账单账户与发票** | 15 |
| **批次 2 · 收款与对账（Stripe）** | 9 |

批次 1：`billing_accounts` / `billing_account_members` / `tax_codes` /
`invoices` / `invoice_lines` / `invoice_events` / `credit_notes`；
每租户连续编号；逐行税码与 GST 分列；周期账单**自动生成草稿 + 人工确认发出**；
对账单、账龄（30/60/90）、逾期清单导出。
**不做**总账、多币种、滞纳金自动计算。

批次 2：Stripe 托管支付页；付款自动核销（一笔可拆分核销，多付成账户余额）；
回调幂等；退款走原路并生成贷记单；现金/转账登记；银行流水 CSV 匹配。

> **架构红线**：租户接**自己的**商户账号，走对方托管页。
> 我们不碰资金、不接触卡数据、**不做 Stripe Connect**。
> 理由不是省事——是不进 PCI 范围、不成为资金通道、不承担争议责任。

### 第三波 · 交出去与老师 ｜ 19 人天

| 项 | 人天 |
|---|:--:|
| **批次 3 · Xero 加购**（三段开关 + 三步向导 + 试跑闸） | 10 |
| **批次 4 · 老师课时与应付清单** | 9 |

批次 4：费率模型五种基准（每课时 / 每小时 / 按到课人头 / 按该课学费百分比 /
每场固定），按老师 × 课程 × 生效日期，改费率不动历史；四个数同屏
（排了 / 实际上了 / 请假按政策计费 / 老师取消不计费）；老师自助确认签收；
输出应付清单 CSV，承包老师可推 Xero 应付账单。

**明确停在「清单」**：不跑批审批、不生成 RCTI、不出银行文件、不算 PAYG/养老金、
不申报。**雇员老师只出清单不推 bill** —— 把雇员工资作为应付账单推进 Xero
会绕开薪资科目造成错账。

### 第四波 · 说得出、看得清 ｜ 22 人天

| 项 | 人天 | 说明 |
|---|:--:|---|
| **通知渠道层**（邮件 + 短信双适配器） | 9 | 见下 |
| **学生成长报告**（加强） | 6 | 见下 |
| **经营报表**（四张 + 下钻 + 导出） | 7 | 见下 |

**通知渠道层**（决定 7）：

- 渠道无关接口 `notify(event, recipient, channels)`；渠道是适配器，不是分支
- **邮件适配器**：SES / Postmark；发信域 SPF / DKIM / DMARC；退信与抑制列表
- **短信适配器**：澳洲服务商；**账号与费用归租户**，我们不做转售、不当计费中间商；
  发送人标识（专属虚拟号码优先；品牌发送名需 ACMA Sender ID 登记）
- 双语模板按收件人语言偏好自动选
- **路由规则表**：哪类事件走哪条渠道。默认——
  账单/逾期/**当天取消** → 短信；例行课前提醒 → 日历订阅（免费）；
  成长报告/对账单 → 邮件
- 送达日志、失败重试、降级链（短信失败退邮件）、退订
- **成本闸**：批量发送前确认条数与预估费用；月度用量看板 + 阈值告警。
  一次误操作不该发出几百条

**学生成长报告**（决定 6）：

- 内容自动汇总自日常记录：出勤与出勤率、每节课笔记与作业、曲目与考级进度、
  老师评语、可选的作品与演奏视频（复用现有同意链）
- **草稿 → 老师编辑 → 发布**：不自动发出未经人过目的报告
- **周期可配置 + 到期自动提醒对应老师**（每 N 节课 / 每学期末），
  管理者能看到「哪几份逾期未写」—— 把官网上的服务承诺变成系统兜底
- 内容板块按工作室开关（不是所有工作室都有考级）
- 双语 PDF；家长门户可见，可生成分享链接（复用 `share_tokens`）

**经营报表**（决定 8）：固定四张，**不做报表生成器**。

1. 收入与开票（按期间 / 按课程类别，GST 分列）
2. 应收账龄（30/60/90 + 逾期清单可导出）
3. 老师成本与课时（计划 vs 实际、课程盈利粗算）
4. 出勤与留存（出勤率、连续缺席预警、课时余额将尽）

每张都能导 CSV，**每个数字都能点开看到底层明细** —— 能下钻的才叫报表，
不能下钻的只是截图。

## 6 · 钱这部分的工程不变量

1. 金额一律**整数分**，任何路径不出现浮点。
2. 发票**开出即不可改**；改错只能贷记单冲销后重开。
3. 每租户**连续编号不跳号**，数据库序列保证并按租户隔离。
4. 所有外部调用与回调带**幂等键**；重放不产生第二张单据。
5. **课时账与钱账是两本**：必须能对上，但任何一方不得覆盖另一方。
6. 每一笔财务写入进**审计日志**。
7. 计费周期按**租户时区**计算（`tenants.timezone` 已有）。
8. **任何套餐或加购限制都不得阻断财务写入。**
9. **读路径永不抛异常**：存量租户没有 `billing_account` 时必须有兜底，
   新表不能把老租户的页面打挂。
10. 上线前必须在**真 Postgres** 上跑端到端；钱的路径不能只靠单测。
11. **财务记录永不进保留期清理**（`prune_event_tables.py` 必须显式排除）。

### 一个必须先修的静默数据丢失风险

`SNAPSHOT_TABLES`（`backend/studiosaas/services/tenant_archive.py:22`）是
**手工维护的元组**，被三处共用：租户归档、独立版 `export_tenant_bundle.py`、
`import_tenant_bundle.py`。

守卫存在（`backend/tests/test_health.py:467`
`test_tenant_archive_snapshot_covers_every_tenant_owned_table`），
但**它是空转的**：`required` 也是硬编码集合，拿一个手写列表比对另一个手写列表。
新增 `invoices` 而两个列表都忘改，测试照样绿。**它只挡删除，不挡遗漏。**

等到要归档的是发票，这就是静默丢财务数据。

**修法**（含在横贯 3 人天里）：把 `required` 改为**从数据库 schema 派生** ——
`information_schema.columns` 里所有带 `tenant_id` 的表，必须要么在
`SNAPSHOT_TABLES` 里，要么在一份**写明理由的显式排除清单**里。
把静默丢数据变成构建失败。

这件事应当**在批次 1 落第一张财务表之前完成**。

### 其余同步点

- 凭据存放：SaaS → Secrets Manager / SSM（roadmap 记录目前仍是本机 env，需一并推进）；
  独立版 → `/etc/pwe-studio`
- 迁移必须幂等，存量租户可重跑
- 独立版安装向导与 `upgrade.sh` 需覆盖新增的服务商配置项
- 独立版交付后我方无技术访问能力，Xero / Stripe 凭据都在客户实例里（既有约定）

## 8 · 明确不做（防过度设计）

| 不做 | 理由 |
|---|---|
| 总账 / 复式记账引擎 | Xero 就是干这个的 |
| 薪资申报（PAYG / super / STP） | 会让软件供应商为客户的税务合规负责 |
| Xero 双向编辑同步 | 两边都能改同一张发票，最终必然对不上 |
| 自建支付处理 / Stripe Connect | 一进资金通道就要承担争议与合规责任 |
| 多级自动催缴序列 | 一条提醒 + 一张逾期清单，剩下交给人 |
| 报表生成器 | 四张固定报表覆盖 90% 的问题 |
| 多币种 / 多国税务引擎 | 先把 AU GST 做对，税码是数据不是代码 |
| 滞纳金自动计算 | 罚钱是商业决策，自动罚款让工作室在客户面前难堪 |
| 短信转售 | 账号与费用归租户，不当计费中间商 |
| 把课前提醒做成短信默认项 | 日历订阅免费且更准；短信只承担必达消息 |

## 9 · 顺带退休一条产品认知

竞品文档 #14 记着「结算刻意保持手动（是商业决策）」。
**该手动的是「发出」，不是「计算」。** 自动算草稿、人工过目发出。
「手动结算」作为长期立场应当退休。
