## 0. 先说一个截图里能看见的 bug（不在你的三项里，但同源）

你第一张截图：**「版块眉题 · English」的占位符是「工作室作品」，「版块标题 ·
English」是「出自这间工作室」，「版块引导语 · English」也是中文。**

原因不在作品板块。`admin-i18n.js` 的 `applyAttributes()` 会翻译
`placeholder` / `title` / `aria-label`，而英文半边字段的占位符**本身就是一句
英文**——于是它被"翻译"成了中文。

**这是全站既有缺陷，不是这一版引入的。** 同样中招的还有至少：

| 字段 | 英文占位符 | 中文界面下显示成 |
|---|---|---|
| `settingPrincipalTitleEn` | Founder & Principal | 创始人 / 主理人 |
| `settingPrincipalQuoteEn` | Short signature line | （已在词典） |
| `settingCoursesLabelEn` | Courses & Classes | （已在词典） |

后果：一个中文界面的工作室主理人，**看不到英文字段该填什么样子**——而占位符
的唯一作用就是给样例。

**修法**：`applyAttributes()` 跳过带 `data-i18n-lock` 的元素，所有 `*En`
输入框加这个属性（可由脚本按 id 后缀批量加，并加测试钉死"英文半边不翻译占位
符"）。约 15 个字段，半小时。

**建议**：这条不必等作品板块，可以先单独发一版。

## 1. 灯箱

要做就做全。以下每一条都是"少了它就不如不做"的。

### 1.1 用 `<dialog>` + `showModal()`，不自己写遮罩

原生 `showModal()` 白送三件最容易做错的事：**焦点陷阱**、**Esc 关闭**、
**惰性外部内容**（`inert`）。自己用 div 写，这三件要手写 200 行且大概率漏。

iOS Safari 15.4+ 支持。**低于此版本不降级成半成品**：检测不到 `showModal`
就保留今天的行为（图片在新标签页打开）。宁可没有灯箱，不要一个关不掉的灯箱。

### 1.2 返回键必须关灯箱 —— 这条是多数实现漏掉的那一条

打开时 `history.pushState`，关闭时 `history.back()`；监听 `popstate` 关闭。

**没有这条，手机用户点返回会直接离开这个工作室的网站。** 他本来只是想退出
一张图。这是灯箱在移动端最大的伤害面，不是"锦上添花"。

### 1.3 键盘与手势

| 输入 | 行为 |
|---|---|
| `←` / `→` | 上一件 / 下一件 |
| `Esc` | 关闭（原生） |
| `Tab` | 只在灯箱内循环（原生） |
| 左右滑 | 上一件 / 下一件 |
| 下滑 | 关闭（移动端的"返回"肌肉记忆） |
| 点击背景 | 关闭 |

**关闭后焦点必须回到打开它的那块瓷砖**，不是回到页面顶部——否则键盘用户
每看一张就要重新 Tab 到原位。

### 1.4 内容与性能

- 只预载相邻两张（n±1）。12 张全预载 = 首屏为了一次点击付十几 MB。
- 计数器「3 / 18」；标题与说明在图片下方，不压在图上。
- 视频条目在灯箱里播放 —— 这才是它该有的尺寸；瓷砖上的播放键改为"打开灯箱
  并播放"，仍然是点击后才请求第三方。
- `prefers-reduced-motion`：无转场。
- 锁滚动用 `overflow:hidden` + `scrollbar-gutter:stable`，否则打开瞬间页面
  会横跳一下（桌面端滚动条消失导致的重排）。

### 1.5 怎么验收

浏览器实测，不是读代码：焦点在关闭后回到原瓷砖；Esc 与返回键都关且**不离开
页面**；灯箱打开时 Tab 走不出去；点开前无第三方请求。

## 2. 上传体验

今天的问题很具体：**一张卡一个 `<input type=file>`，一次一张。** 传 20 件
作品 = 20 次（新增卡 → 点击 → 选文件 → 等）。而且：

- 没有拖拽、不能多选；
- 没有进度，手机网络下传一张 8MB 照片看起来像卡死了；
- **不压缩**——手机直出照片轻松超过单文件 10MB 上限被拒，而工作室不知道为什么；
- 每次上传后整块重渲染，正在输入的说明会丢焦点。

### 2.1 客户端先压缩（收益最大的一条）

上传前用 canvas 缩到**最长边 2400px、JPEG q0.82**：一张 24MP 手机照片从
~8MB 变成 ~500KB。

- 不再撞 10MB 上限；
- 媒体额度能多放十几倍的作品；
- 主理人在手机上传 20 张的等待从几分钟变成十几秒。

必须用 `createImageBitmap(blob, {imageOrientation:'from-image'})` 处理 EXIF
方向，否则竖拍照片会躺下——这是压缩最常见的坑。

2400px 是有理由的：2× DPR 的屏幕上主位瓷砖最宽约 1100px，2400 够用且留余量；
再大只是让访客替我们下载看不见的像素。

### 2.2 一个拖放区，多选，乐观渲染

- 标签页顶部一个拖放区：拖文件进来，或点击多选。
- 每个文件**立即**变成一张卡，用 `URL.createObjectURL` 显示本地预览 + 进度条
  ——主理人马上看到板子在成形，而不是盯着一个转圈。
- 队列并发 2，不是 20 条连接一起冲。
- **单个失败只影响单个**：那张卡标红可重试，其余照传。

### 2.3 不要在打字时重建 DOM

改成按 key 更新而不是整块 `textContent=''` 重建，否则上传完成会打断正在输入
的说明。（今天的 `renderShowcaseItems()` 就是整块重建。）

### 2.4 顺带

- 显示额度用量「已用 120MB / 2GB」，就在拖放区旁边。
- 拖拽排序，**并保留 ↑↓ 按钮**——拖拽对键盘和读屏用户不可达。

## 3. 取消 12 张上限 + 引入分类

这一项是三项里唯一改数据结构的，所以要一次做对。

### 3.1 分类

```
website_profile.showcase_categories = [
  { id: "oil",       label: {zh:"油画",   en:"Oil"} },
  { id: "portrait",  label: {zh:"人像",   en:"Portrait"} },
]                                        // 最多 8 个，有序
```

每件作品加 `category_id`（可空 = 未分类）。

- **删除分类不删作品**，只把作品变成未分类。作品是主理人的劳动，分类只是抽屉。
- id 由服务端生成（短随机），不用标签派生——否则改名就等于换 id，所有作品脱钩。

### 3.2 作品搬出 `/brand`，走自己的接口

**这是本方案最重要的一条决定。**

取消 12 上限后 `showcase_items` 会无界增长，而 `/brand` 是**关键路径**——
门户的每一个字、每一张图都在这一个响应里。本周刚发生过：一个字段解析失败，
五个门户整页空白。**往这条路径上挂一个无界列表是反方向的。**

改成 `/v1/public/<slug>/showcase?category=&page=`，与已有的 `/programs`、
`/public-gallery` 同构。

**代价必须明说**：这会重新制造 v8.5.3 那个竞态——开关在 `/brand`，内容在
`/showcase`，谁后到谁说了算。所以**从第一行代码起就走 `state.sectionsOff`
模式**，并且进 `test_section_switches.py` 的 `DATA_FED` 集合。这不是"注意
一下"，是设计前提。

### 3.3 上限：换成展示上限，不是存储上限

取消存储上限，但**首屏只渲染 12 件 + 「加载更多」**。

理由：一面 200 件的墙对访客不是"更有实力"，是"看不完"；而且 LCP 会塌。
限制从"你只能存 12 件"变成"我们一次只让访客看 12 件"——**限制访客的注意力，
不限制主理人的作品**。

分类因此成为主要导航：门户上是一排筛选芯片（全部 / 油画 / 人像 …），点击在
已加载的数据里即时过滤，不足则再取一页。

筛选后**第一件仍然是主位**（φ 布局规则不变）——每个分类都有它最强的一件。

### 3.4 后台

- 分类管理器：新增 / 改名 / 排序 / 删除（删除时提示"N 件作品将变成未分类"）。
- 每张卡一个分类下拉。
- 编辑器本身可按分类过滤——50 件以后，一条长列表没法用。

### 3.5 要一起改掉的地方

`SHOWCASE_ITEM_LIMIT` 现在有三处副本：`api_v1.py`、`studio-admin.html`、
Owner 手册。取消时三处都要动，测试里也有一条断言。

## 5. 我不建议做的

- **不做无限滚动**：作品集是要看完的，不是刷的；"加载更多"给得起控制感。
- **不做每张图的独立 URL**：单页应用里做深链要动路由，收益是分享单张作品——
  等有人真的要求再说。
- **不做视频自托管**：这条在第一轮已经决定过，不重开。
