# My Music Staff 对比 · 我们该学什么、该守住什么

> 考察日期 2026-08-12，对照 PWE Studio v9.9.1。
> **只看了对方的对外站点**（首页、定价页、注册页），没有产品内部截图；
> 「产品逻辑」一节是从功能描述反推的，不是实测。

`mymusicstaff.com` 自称「私人音乐教师与音乐工作室的第一管理软件」。
它和我们重叠的部分很大：学员管理、排课、公开网站、家长门户、试听预约。
不重叠的部分也很清楚：他们做在线支付与自动开票，我们不做。

---

## 一句话结论

**他们把「掏钱之前」的每一步都铺平了，我们把「掏钱之后」的每一步做扎实了。**

对方最值得学的不是某个功能，是**一条不需要跟人说话就能看到产品的路径**：
30 天试用、不要信用卡、注册只问一个问题、价格带计算器写在页面上。
我们最不该抄的是他们的建站器——拖拽自由意味着工作室可以发布一个空版块、
可以做出读不清的配色，而我们的公开表面契约与配色求解器从机制上不允许。

# 一 · 宣发（差距最大）

| # | 他们怎么做 | 我们现在 | 建议 |
|---|---|---|---|
| 1 | **一个价格，全功能**：`$22.95/月 + 每多一位老师 $5.95`，没有功能分级 | starter / studio / growth，含 `showcase_limit` 15/60/150 与学员上限 | 不必改模型，但要让访客**一眼算出自己要付多少** |
| 2 | **定价页有实时计算器**：「你有几位老师？」拖一下出月费 | 首页 `#plans` 三张卡 | **做一个**：输入学员数与团队人数 → 推荐套餐 + 月费 + setup 区间 + 首年合计 |
| 3 | **30 天免费试用，不要信用卡** | 人工开通 + setup fee AUD 299–999 | 漏斗上最大的一条差距。见下方「如果只做三件」 |
| 4 | **注册只问一个问题**：「就我一个」/「我有多位老师」 | 无自助注册 | 任何自助入口都应当只问这一个问题 |
| 5 | **社会证明带真实分布**：4.8 分 / 760 条，5★ 82%、4★ 16%、3★ 1%、2★ 1%、**1★ 0%** | 无 | 1★ 是 0% 这件事本身就是说服力；等我们有评价再做，**不要编** |
| 6 | **每个功能板块配一条署名评价**，紧挨着那组要点 | 无 | 证据紧挨主张，比单独的「客户评价」区有效 |
| 7 | **首屏四个词让访客对号入座**：上门私教 / 音乐学校 / 流动教师 / 琴行课程 | 行业预设已有这套分类，首屏没用 | 把已有的行业预设名提到首屏 |
| 8 | **六个板块全是结果 + 动词开头要点** | 首页偏能力叙述 | 可直接套用的模板，见下 |
| 9 | **定价页 FAQ 只答掏钱前的疑虑**：能退款吗、学员数有上限吗、短信另收费吗、自建网站要另付托管费吗 | FAQ 在租户站上，平台自己的 FAQ 在首页混排 | 把「钱」的问题集中到定价页 |
| 10 | **90 天退款承诺**写在定价页 | 无任何保证条款 | 需要商业决策；哪怕是「首月不满意退 setup 费」也比没有强 |
| 11 | **「Getting Started Guide」是首页 CTA** | `/zh/manual` 存在但不是入口 | 手册是获客资产，不只是售后 |

# 二 · 产品逻辑

| # | 他们的做法 | 我们的现状 | 我的判断 |
|---|---|---|---|
| 12 | **试听自助预约会占住时段**：「Hold the weekly slot while students or parents decide」 | **刻意不占座**，批准那一刻才复核容量 | 两种都站得住。建议**限时占位**（如 48 小时自动释放）——既提高转化，又不让没人处理的申请挡住真会来的家庭 |
| 13 | **线索 / 候补是一等对象**，自助预约自动打标签入池 | 有 `class_bookings` 待审核与报名，无线索管道 | 值得做。约课申请天然就是线索 |
| 14 | **按日程计费**：排了什么课生成什么账单，自动发票 + 逾期提醒 + 滞纳金 | 结算刻意手动（是商业决策） | 中间态：**自动生成草稿账单，人工确认发出** |
| 15 | **双向日历同步**（Google / Outlook） | 有 ICS 导出 | 老师真正生活在自己的日历里；双向同步是留存功能 |
| 16 | **自动短信 + 邮件提醒** | CMS 内通知，无外发短信 | 短信在澳洲有成本，但「课前提醒」是家长最有感的一条 |
| 17 | **学员端自助请假/取消**，由工作室预设的政策与截止时间约束 | 学员专区偏只读 | 规则设一次、门户执行——这是把前台从电话里解放出来 |
| 18 | **集成清单点名列出**：Stripe、PayPal、Wix、Squarespace、WordPress、Zoom、Google Calendar、Outlook、QuickBooks、Zapier | 无 | 把名字写出来本身就是信任信号 |
| 19 | **导入现有学员名单是头部功能** | 正在写 Let's Paint importer（一次性脚本） | **把它提升成产品功能**：换供应商时最大的摩擦就是搬家 |
| 20 | **可嵌入外部站点的登录挂件** | 默认「我们就是你的网站」 | 他们承认工作室可能已有网站。一个可嵌入的报名/登录挂件成本不高 |
| 21 | **多老师工作室有课酬跟踪** | 无 | 与我们的 `memberships` 角色模型不冲突 |

# 三 · UI / UX

| # | 观察 |
|---|---|
| 22 | 营销首页是**一条单列滚动**，移动端顶部只有汉堡 + 一个 CTA——干脆绕开了导航。对照我们刚修的导航标签问题：**营销页不需要复杂导航** |

# 四 · 我们更好的地方（别抄反了）

1. **同意驱动的学员作品**：append-only 同意事件，撤回即刻下架。他们有文件共享，看不到同意模型。
2. **公开表面契约**：`intent × contentReady × dependencyReady` + 原因码。拖拽建站器允许发布一个空版块；我们从机制上不允许。
3. **双语是产品属性**，每个字段都是 `{zh, en}` 对，不是界面语言开关。
4. **一个强调色解出整套配色并校验对比度**。拖拽建站器让工作室能做出读不清的站。
5. **套餐上限只管发布、不管存储**，降级绝不删数据。
6. **公开页面的数字来自产品实际执行的套餐表**，页面写不出系统不承认的额度。

---

# 五 · 如果只做三件

1. **一条不用跟人说话就能看到产品的路径。** 不必是免费试用——一个**永久在线的演示租户**（可读可点、每晚重置）配合「预约演示」就够了。这是漏斗上最大的一块。
2. **独立定价页 + 计算器 + 掏钱前 FAQ + 某种保证。** 价格已经写在首页了（`#plans` 从 `public_plan_rows()` 读），缺的是**专属地址**、**算得出总数的交互**和**钱的问题集中回答**。
3. **限时占位的试听预约。** 把我们「不占座」的正确性和他们「锁住犹豫期」的转化力合起来。

# 附：一条已经作废的旧约定

`docs/design/` 与记忆里长期写着「官网页面里不许写价格」。
**这条已经不成立**：`product-home.html` 的 `#plans` 区块从 v8.2.x 起就渲染真实价格，
`/v1/public/plans` 与 `/pricing.md` 也是公开的，
`public_plans()` 的注释直接写着「Prices are public by definition」。
2026-08-12 由产品方确认：**价格可以写，并且要做独立定价页。**
