## 0. 组织方式：按共用机制分组，不按页面分组

四份来源里的 20 多条如果按页面排，会变成「排课页做三件事、设置页做一件事、
工作台做四件事」，而其中**六条其实共用同一套 `Tabs`/`TabPanel` 原语和同一个
作用域路由**。按页面排就会把同一件事拆成三次改、三次测、三次 i18n。

所以本文按机制分成 **A–F 六组**：

| 组 | 共用什么 | 条目 |
|---|---|---|
| **A** | `Tabs`/`TabPanel` 原语 + `?section=` 作用域路由 | 3 |
| **B** | 纯版面合并，不引入新原语 | 3 |
| **C** | 一个行内确认组件 | 1 |
| **D** | 排课页的只读推导与内嵌记录 | 4 |
| **E** | 门禁 | 1 |
| **F** | 对外页面（不碰 CMS） | 6 |

## A. 分段：三处共用一套原语

`components.jsx:228/268` 的 `Tabs`/`TabPanel` 已经存在。下面三条都要用它，
**同批做才只需要一次原语加固、一轮 i18n、一套测试契约**。

### A.1 设置页 tab 条：手机上选中项被裁到视口外（★★★ · 已实测）

`CMS_Settings_Restructure.md` #8 当时估算约 540px 内容对 343px 可用宽，
并明确拒绝在没实测前定级。**本文实测了：**

| 视口 | tab 条可用宽 | 内容宽 | 溢出 | 后 4 个分区的选中 tab |
|---|---:|---:|---:|---|
| 375×812 | 343 | **654** | **311px** | ❌ 在可见范围外 |
| 390×844 | 358 | **654** | **296px** | ❌ 在可见范围外 |
| 1440×900 | 1152 | 1152 | **0** | ✅ |

七个标签：`账号与安全 / 团队与权限 / 运营默认 / 开票信息 / 集成 / 数据维护 / 工作区链接`。
**前 3 个在可见范围内，后 4 个不在。**

后果不是「要横向滑一下」，是**深链到后四个分区时手机上看不出选中了什么**——
条上显示前三个（都未选中），下面的面板却是第五个。

**根因已确认仍在：** `setSettingsSection`（`cms-app.jsx:136–141`）设置状态、
切页、同步路由，**没有把选中的标签滚进视口**。全文件仅三处 `scrollIntoView`，
都在排课/课程页。

**修法：** `setSettingsSection` 与深链解析后各补一次
`scrollIntoView({inline:'nearest', block:'nearest'})`。**先修这个，不要先加渐隐遮罩**——
遮罩让溢出好看一点，但看不出选中项这件事原样保留。

> **结论：设置页不需要重构。** 实测结构是健康的（1 个面板、1 条标签、
> 桌面 900 / 手机 1005 总高、0 横向溢出）。方案 B 已经生效。**只有这一个缺陷。**

### A.2 排课页页内标签（阶段二 · 乙）（★★★）

执行清单见 `CMS_Roster_Split_Plan.md` §四 阶段二，第 9–19 步。此处只记整合要点。

**为什么仍然要做（阶段一之后）：** 版面收益只有净 60–110px，是边际的。
真正买到的是三件别的事，**其中第一件才是主要理由**：

1. **对 teacher / 助教，整个「排课」半边是按不动的。** 固定课表的增删改在

   放在页尾是「不挡路」，放进另一个标签是「与我无关」。
2. `排课设置` 拿到自己的 URL（`?view=roster&section=plan`），通知与支持链接可直达。
3. 概览条可以真正吸顶——只有在「签到」这一个标签里，粘性条上下才是同一件事。

**实测现状（owner，2026-09-03）：** 桌面总高 1220、名单起点 y=**514**（阶段一预测 542，兑现）；
手机总高 1615、当日名单卡在 y=408。**阶段一的收益已经坐实，乙是在健康基础上的下一步。**

## B. 工作台：把六块合成一块

实测 dashboard 是全站最拥挤的页面，**而它是落地页**：
桌面 2243px / 10 个顶层块 / 44 个按钮，手机 **3410px / 11 块**，第一屏只装得下 2 块。

### B.1 「最近操作」移出落地页（★★★ · 先做这条）

实测 **722px，是落地页最高的单块**，位置 y=1413（桌面）/ y=2630（手机）——
没人会滚到那里。而 `logs` 是独立导航项（实测 29 行、桌面 3098px），干的是同一件事。

落地页保留一行「最近 N 条操作 →」链接。

**收益：桌面 −32%、手机 −21%，顶层块 −1。改动最小、收益最大。**

### B.2 四条琥珀条 + 长期未到访 → 一个「需要注意」区（★★★）

现状是四条语义完全同类的提醒条，被大块隔开：

| y（桌面） | 高 | 块 |
|---:|---:|---|
| 867 | 72 | 有待审核的注册申请 |
| 959 | 210 | 长期未到访 — 12 名学员 |
| 1189 | 78 | 应收 $1963.50 |
| 1287 | 106 | 课时预警 — 2 名学员 |

桌面合计 **466px**，手机 **986px**（`长期未到访` 手机上从 210 涨到 **698**，学员胶囊换行）。
它们是 v5.3 → v10.7 逐版本累加的，每条单看都合理，摞起来是一条提醒走廊。

**并且「待审核」在这一页出现三次**：侧栏导航徽标、`今日指挥台` 里的计数格
（`dashboard.jsx:77`）、独立琥珀条（`:287`）。三处同一个数字、同一个去处。

**合并为一个区块，每类一行，名单点开才展开：**

```
需要注意 (4)
  ├ 4 位学员等待审核                      → pending
  ├ 12 名学员有余额但超过 90 天未上课      → students?filter=inactive
  ├ 3 张未付清，其中 2 张逾期 · $1963.50   → billing
  └ 2 名学员余额 ≤ 2 课时                  → students?filter=low
```

同时删掉 `今日指挥台` 里的 `待审核` 计数格。

**收益：桌面 676 → ~200px，手机 986 → ~240px，顶层块 10 → 5。**

> **注意：合并的是块，不是信息。** 四条跳向四个不同页面，
> **不要**合成一个汇总数字——那样就没法点了。数据源、权限投影、跳转目标全不变。

### B.3 `学员专区与作品发布` 下移（★★ · Lee 已确认不常用）

实测占落地页第 3 块，桌面 152px、**手机 380px**——首屏黄金位置。
Lee 确认不常用，移到「需要注意」区下方。

**`经营真账（估算）` 保持折叠**（Lee 已确认）。实测折叠态 46px，成本极低。

## C. 行内两段式确认（★★★ · 一个组件，三页受益）

来自 `Learning_From_LetsPaint_CMS` §2.6：

```
再点确认 · 8→7 课时      ← 确认文案是算术，不是问句
```

三个设计点：**确认显示将要发生的结果**（"确定吗"提供不了新信息）、
**不用模态框**（按钮自身变确认态）、**3 秒自动解除**（走开了就不算数）。

**为什么放进这一轮：** 实测 `roster` 55 个按钮、`students` 53 个，是全站最高，
但两页的**块结构都是健康的**（名单 y=514 / y=327，都在首屏内）。
这不是排列问题，是每行操作太多、每个操作都要走一趟对话框。

顺带解掉 Platform Admin 审计记录的「两套对话框系统」未解决项
（`openModal()` 与 `window.confirm()` 并存，CMS 产物中 `window.confirm(` 1 处）。

**先做这条，再看 roster/students 是否还需要收纳按钮。**

## D. 排课页功能补齐（来自 Let's Paint，与 A.2 同批）

这四条都落在排课页，与 A.2 的分段是同一批改动，**放在同一个 PR 里**。

### D.1 周日期条 + 人数徽标（★★★）

现状只有 `shiftDate` 的前一天 / 后一天（`scheduling.jsx` 619 行无日期条，
产物中 `rosterCounts` 0 次）。排课的实际动作是「看看这周哪天空着」——
一天一天点过去，是把空间问题变成了序列问题。

### D.2 派生的「缺席」（★★★ · 只在显示层）

排了课 + 日期已过 + 无签到 = 缺席。**不是存储字段，是推导的**，没人需要维护。
现在一节过去了没人来的课，和一节明天的课，界面上长得一样。

> **⚠ 绝不要把 `done`/`absent` 加进 `daily_roster_entries.status` 枚举。**
> 现枚举是 `scheduled | makeup | cancelled`，出勤维度不在里面——这是对的。
> Let's Paint 的 `status` 能存 `done`，为此写了**两道守卫**（读路径降级、写路径拒绝）。
> StudioSaaS 靠约束免疫，改枚举等于把这个结构优势换成两段代码。

### D.3 临时签到也要出现（★★）

有签到记录但当天没排课的，照样显示为已完成。**现实胜过计划**——
学员没排课直接来了、老师现场加人，每周都发生。

### D.4 当日变更记录内嵌（★★）

九类动作、当天、最近 8 条、默认折叠，嵌在排课页底部。
「今天这张表怎么变成这样的」是排课页当场的问题，答案应该在同一屏，
而不是在 `logs` 页。

### D.5 月视图展开（★★ · 只存本地）

42 格固定 / 周一起始 `(first.getDay()+6)%7` / **末行整行属下月则裁掉** /
**人数为 0 不显示徽标**（"排过又清空"的残留真实存在）。
展开态写 `localStorage`，**不进数据库、不跨设备**（Lee 已确认）。
日期格需 `min-height:var(--tap-min)`。

### D.6 导出工具组分层（★）

`role="group"` 把「日历 / 日报」归组，与签到主操作分层；每个按钮
可访问名称 + 用途提示两层文本。

## E. 把 CMS 加进浏览器门禁（★★★ · 收尾，防止 A–D 退化）

`ui_matrix.py` + `ui_matrix.yaml` 是真 Playwright 多视口门禁
（375/768/1280 × 3 语言），但 `pages:` 里**只有三个公开页面，没有任何 CMS 页面**。

本方案 §A、§B 的每一条收益都是**版面数字**，而版面数字没有任何东西看着——
下次改动后不会有人知道它退化了。本文那些表格是手工跑出来的。

**建议断言三件事**（都在本文有实测基线）：

| 断言 | 基线 |
|---|---|
| 每页顶层块数 ≤ 阈值 | dashboard 改后应 ≤ 6（现 10/11） |
| 无横向溢出 | 现全站 0，保持 |
| **tab 条的选中项必须在可见范围内** | 直接看住 A.1，且对 A.2/A.3 同样成立 |

> `ui_matrix.py` 刻意不进 `verify_local.sh`（发布门禁不该依赖浏览器下载）——
> **这个决定是对的，不要改。** 加页面进 yaml，不动它的运行时机。

## F. 对外页面（不碰 CMS，可完全并行）

来自 `Learning_From_LetsPaint_CMS`。与 A–E **零文件重叠**，可以并行推进。

### F.1 `hero_shape` 上配色管线（★★★ · **唯一待拍板项**）

`organic` / `oval` / `square` 三形状**已实现**（曲率与 Let's Paint 逐字符相同，
还多了 hover 变形）。问题只是它住在 `hero_profile` 里、固定默认 `organic`，
而 `presets.py:425` 的 `STYLE_SHAPE` 已经是那条线（已挂 `button_style` + `font_mood`）。

**做法：新增第四个值 `"auto"` = 跟随视觉风格。** 新租户默认 `auto`，
存量的 `organic` 原样不动（它现在是显式选择，渲染结果不变）。
零迁移、零视觉变化。这个 `auto` 模式**在同一个函数里已有先例**——
`secondary_cta_target` 就在其上方 6 行，注释写着
*`auto` preserves old tenants without guessing at save time.*

**待你拍板的映射**（五个我认为无争议，三个想听你的）：

| style_id | 建议 | 备注 |
|---|---|---|
| `atelier-clay` / `cedar-grove` / `custom` | `organic` | 无争议 |
| `harbour-calm` | `oval` | 无争议 |
| `arcade-lime` | `square` | 无争议 |
| `vintage-press` | `organic` | Lee 拍板 2026-09-03：`button_style` 是 soft，形状跟按钮走 |
| `studio-ink` | `square` | **已经是 sharp，形状该跟上** |
| `recital-plum` / `rehearsal-rose` | `oval` | **rounded 按钮对应椭圆** |

### F.2 材质：加纹理不加颜色（★★★ · 性价比最高）

一张纹理图 `mix-blend-mode: soft-light` + **8% 不透明度**。混合模式让纹理
**跟着底色走，不引入任何自己的颜色**——这是唯一一种不违反「单一颜色来源」
又能加质感的手段。`.pull` 深色区块（现有 2 处）是现成落点。
实测公开模板 `soft-light`/`multiply` **0 次**。

### F.3 `attr()` 水印（★★★）

`content: attr(data-medium)` + 68px 衬线 + **5.5% 不透明度**，
用已经在 DOM 里的数据做装饰。课程分类、乐器名直接抬成装饰层，多语言天然成立。
实测 `attr(` **0 次**。

**两个坑：** 字号必须落在封闭尺度内（Let's Paint 曾用 92px 溢出卡片，
而 StudioSaaS 的 `.course` 同样没有 `overflow:hidden`）；不透明度必须 5–6%。

### F.4 揭幕式入场（★★）

`clip-path: inset(0 0 100% 0 round var(--radius-card))`——
**裁切路径带着卡片自己的圆角**，揭幕中边缘始终是圆的。
时长写 `calc(var(--dur-enter) * 4)` 而不是硬编码，这样减弱动效下自动归零。
实测 `clip-path` **0 次**。

### F.5 滚动进度条（★★）

只用 `transform: scaleX()`，渐变第二色用 `color-mix` 从强调色派生，不新增 token。

### F.6 每条新动效自带减弱动效处理（★★★ · 与 F.2–F.5 同批，不单独排期）

StudioSaaS 现有做法**比 Let's Paint 更好**：减弱动效下把 `--dur-enter`/`--dur-exit`
归零，所有引用它们的过渡自动失效，不需要 `*!important` 通配轰炸。

**但归零覆盖不到三类**，而 F.2–F.5 每条都踩中一类：

| 项 | 归零能否覆盖 | 必须补 |
|---|---|---|
| F.4 揭幕 | ✅（时长用 `calc(var(--dur-enter)*4)`） | — |
| F.2 材质 | ❌ 不是动效 | `body{background-attachment:scroll}` |
| F.5 进度条 | ❌ JS 驱动 | JS 侧查 `matchMedia` 后不注册监听 |
