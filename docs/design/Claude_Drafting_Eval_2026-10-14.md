# Claude 起草 · 评测记录

> 2026-10-14。Lee 同意「先评测」，API 用法由「API总规划调度」会话按 Lee 当天的授权给出，上限 US$15。
> 全部数据是合成的，不含任何租户、家长或学员数据。脚本：`backend/scripts/eval_drafting.py`。原始结果在 `outputs/drafting-eval-2026-10-14*`（被 git 忽略）。

## 结论

1. **建议用 Claude Haiku 5.5（`claude-haiku-5-5`）。** 语气分与 Opus 5.5 相差在误差内（3.52 对 3.56），三个模型都没有编造数字；Haiku 的起草费用约为 Opus 的 1/23，同步调用中位数 2.6 秒。
2. **约课回复要有员工的要点。** 没有要点时，「询问」和「婉拒」只能留占位符，分数最低；加上「想说的要点」后，Haiku 从 3.43 升到 3.98，Opus 从 3.36 升到 4.15。这一栏已加进对话框。
3. **数字核对有用，而且严格。** 修掉两类时间写法的误报后，它在 120 条约课回复里只标出一类真问题：模型自己推算出的「同一周的周六（10月17日）」。这种日期可能算对，也可能算错，正该让员工看一眼。
4. 总花费 **US$3.93**（1,983 次请求），在 US$15 上限内。

## 怎么评的

- 6 类消息 × 40 条合成记录 = 240 条，中英各半。约四分之一故意缺一个事实（课包、付款方式），看模型会不会说出来。
- 每条记录三个模型各起草一次，走批处理（半价）。批处理里不设缓存断点：共享前缀约 300–400 token，同批请求互相读不到缓存。
- 脚本核对每一条：编造的数字或日期、语言是否对、是否过长、有没有承诺折扣或退款、缺的事实有没有说。
- 语气评分：每类每个模型抽 14 条（约课回复复测时全部 40 条），由 Sonnet 5.5 打 1–5 分，评分者看不到是哪个模型写的。

### 评分者校准

20 条草稿同时让 Sonnet 5.5 和 Opus 5.5 评分：全部相差在一分以内，7 条完全相同。Sonnet 稳定地比 Opus 严约 0.6 分，但高低排序一致。比较三个模型看的是相对高低，所以全量用 Sonnet（「API总规划调度」的建议）。

## 评测过程中改掉的东西

| 发现 | 改动 |
|---|---|
| 第一次测试草稿按名字猜了学员性别（"his"） | 系统提示加一条：不猜性别，重复名字或用中性说法 |
| 第一轮合成数据自相矛盾（工作室名与落款不符、美术和钢琴笔记混在一起、笔记多于出勤），模型忙着指出矛盾 | 生成器改成每个工作室一个行业；第一轮作废，评分批次取消（未执行、未计费） |
| 续费提醒的任务说明写「只剩几节」，工作台却会列出余额为 0 的学员 | 改成「只剩几节或已用完」 |
| 被标出的数字全是 24 小时制写成 12 小时制（16:30 → 4:30 pm），以及中文「下午4点30分」 | 核对规则认这些写法；各加一条测试 |
| 「询问」「婉拒」的约课回复只能留占位符 | 对话框加「想说的要点」（最多 300 字），作为事实交给 Claude；隐私政策第十一节写明 |

## 局限

- 合成数据不等于真实工作室的记录和语气。上线后应抽看真实草稿。
- 语气分来自一个模型评分者，不是家长。每个模型每类 14 条，类型之间的差别多在误差内。
- 没有测中英以外的语言，也没有测极长的课堂笔记。
