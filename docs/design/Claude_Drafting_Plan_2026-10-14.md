# Claude 起草 · 只起草，人确认后再发

> 状态：**方案**，没有写代码。2026-10-14，对照 PWE Studio v10.21.1。
> 方向来自 Lee 2026-10-14：「只起草，人确认后再发，而且还可以更多的使用 API，设计一下」。
> 模型和价格取自 Claude API 参考资料（缓存于 2026-10-06），美元计价。

---

## 结论

1. **做成「起草」按钮，放在已有的工作界面里。** 员工点「起草」，Claude 根据这一条记录写一段，员工修改，员工自己发出去。Claude 不发送任何东西，不改任何数据。
2. **第一阶段用员工自己的邮件或短信应用发送。** 复制，或者一键打开写好内容的邮件／短信。工作台的生日祝福已经是这个做法。好处：不需要发信通道，不需要接 Cloudflare，信从租户自己的邮箱和号码发出，家长回复直接到租户。
3. **最值得先做的两处：** 成长报告评语初稿；工作台每一行例外旁边的跟进消息。
4. **费用很低，但要先定谁付。** 一条短消息的成本按模型不同约在 0.03 到 1.2 美分之间（见第五节）。
5. **动手之前有一件必须先定的事：** 家长的信息会交给 Anthropic 处理，处理在澳大利亚以外。隐私政策和给租户的条款都要改，租户要能自己选择打开。按 `AGENTS.md` §24，这是改变个人信息的使用。

## 一 · 用在哪里（按价值排序）

### 第一阶段

| # | 位置 | Claude 起草什么 | 依据的事实 |
|---|---|---|---|
| 1 | 学员档案 → 成长报告 | 评语初稿，一到两段 | 这一周期的出勤、课堂笔记、曲目或作品、考级进度（报告 `content` 里已有） |
| 2 | 工作台 · 课时快用完 | 续费提醒 | 剩余课时、上次上课日期、租户的课包名称和价格 |
| 3 | 工作台 · 排了课连续没来 | 关心问候，不是催促 | 连续次数、上次来的日期 |
| 4 | 工作台 · 未付清发票 | 礼貌的付款提醒 | 发票号、金额、到期日、付款方式说明 |
| 5 | 工作台 · 补课额度快到期 | 邀请约补课 | 到期日、可选的补课时段（只用系统给的） |
| 6 | 工作台 · 等回复的报名和约课 | 回复初稿 | 申请的班次和日期、剩余名额 |

### 第二阶段

| # | 用法 | 说明 |
|---|---|---|
| 7 | 约课申请批准／婉拒的回复 | 婉拒时附上其他有空位的时段。时段只能从公开课表的数据里来 |
| 8 | 按家长语言起草或翻译 | 付款方账户已有 `language` 字段（`zh` / `en`）。一键把中文稿改写成英文，或反过来 |
| 9 | 报名留言整理 | 从家长的自由留言里提取年龄、想学什么、可上课时间，填进报名记录的空栏，员工确认后才保存 |
| 10 | 老板的经营小结 | 把工作台例外和本月数字写成一段话。先做成按钮；定时生成要等调度器的决定 |

### 不做

- 不让 Claude 自动发出任何消息。
- 不让它决定计费、退款、出勤、名额。
- 不给学员打分或下评价。
- 不做后台里的聊天助手：pwe-ai-bots 那边「给老板用的 PWE Assist」已暂停（2026-10-10），这里只做起草，不重叠。

## 二 · 员工看到的流程

1. 在一条记录旁点「起草」。
2. 等一到几秒。按钮显示正在起草；失败时说明原因，员工照常手写。
3. 出现一个可编辑的文本框，上面列出 Claude 用到的事实（金额、日期、次数），方便核对。
4. 如果 Claude 缺少某个事实（例如不知道付款方式），文本框上方写明「缺少：……」，而不是编一个。
5. 员工修改。
6. 员工选「复制」「用邮件打开」或「用短信打开」。系统只记录「起草过一次」，不记录内容。

成长报告的评语直接填进现有的评语框，老师照常保存、发布。发布仍要有发布权限的人做。

## 三 · 工作方式

### 请求

- 新接口 `POST /v1/drafts`，参数：起草类型、记录 ID、语言。权限跟着那条记录走：能看这条记录的人才能为它起草。
- 服务端按类型从数据库取事实（照常绑定租户，受 RLS 约束），组成请求，调用 Claude，返回草稿。
- 浏览器不接触 API 密钥，也不直接调用 Claude。

### 发给 Claude 的内容：只给写这段话需要的

- 给：学员的名（不带姓）、称呼家长的方式、与这类消息相关的数字和日期、租户名称、租户写好的签名和语气说明。
- 不给：电话、邮箱、住址、生日、照片、其他学员的任何信息。
- 租户的风格：租户可以写一段「我们说话的方式」和签名，起草时附上。已有的消息模板（例如生日祝福）也可以作为语气示例。

### 返回的格式

用结构化输出（`output_config.format` 的 JSON schema），固定三个字段：

| 字段 | 内容 |
|---|---|
| `subject` | 邮件标题（短信为空） |
| `body` | 正文 |
| `missing` | Claude 需要但没有拿到的事实，列表 |

### 防止编造

- 系统提示写明：只能使用给出的事实；不承诺折扣、退款或补偿；不确定就写进 `missing`。
- 界面把草稿里出现的数字和日期，与给出的事实逐一对照，对不上的标出来。
- 最终由人看过才会发出去。这是整个方案的安全底线。

### 模型

- Claude API 参考资料的默认是 Claude Opus 5.5（`claude-opus-5-5`）。
- 写短消息，Claude Haiku 5.5（`claude-haiku-5-5`）很可能够用，便宜约 40 倍。pwe-ai-bots 2026-10 的评测里，Haiku 5.5 在产品站问答上 44 题全对。
- **建议：先建一套评测（每类约 40 条合成记录），用同一套题比较 Opus 5.5、Sonnet 5.5、Haiku 5.5，再由 Lee 定。** 评测看三件事：有没有编造数字、语气是否合适、中英文是否自然。
- Opus 5.5 和 Sonnet 5.5 默认带安全拒答的服务端回退参数；拒答时界面说「没能起草」，员工手写。

### 缓存与批处理

- 每类消息的系统提示固定不变，放在请求最前面，用提示缓存。缓存读取约为正常输入价的一折。
- 老板小结这类不急的内容，可以走批处理接口，价格减半。逐条起草是员工在等，不走批处理。

### 密钥和限额

- 生产主机的环境文件里放一个专用的 API 密钥。Lee 自己放，不经过会话。这个密钥与会话里用的分开。
- 在 Anthropic 后台给这个密钥所在的工作区设月度花费上限。
- 每个租户一个月度起草次数上限，做法照搬短信的额度（`notification_channels.monthly_quota`）。到了上限，按钮说明原因。
- Edition：默认关闭。客户愿意的话可以填自己的密钥。

### 记录

- 每次起草记一行：租户、操作人、类型、记录 ID、模型、输入输出 token 数、费用、成功与否。
- **不保存草稿内容**，也不保存发给 Claude 的事实。原因：内容含家长信息，留着没有用处，只增加风险。

## 四 · 隐私与条款（动手前必须先定）

- **现状：** 隐私政策第 5 节写「除加密备份外，我方不会为自身目的将工作室的个人信息传输至境外」。第 10 节讲的是我们自己网站上的助手，不涉及租户数据。
- **起草会改变这一点：** 家长和学员的部分信息会交给 Anthropic 处理。按我们 2026-10-10 写进第 10 节的事实：Anthropic 不用这些内容训练模型，最多保留 30 天后删除（违反使用政策的内容和法律要求保留的除外），处理可能在澳大利亚以外。
- **角色：** 租户是信息的控制方，PWE 替租户处理，Anthropic 是 PWE 的下级处理方。按澳大利亚隐私原则第 8 条，跨境披露要能告诉家长。
- **建议的做法：**
  1. 隐私政策新增一节「用 AI 起草消息」，照上面的事实写。
  2. 服务条款写明这是租户自己打开的功能，打开即表示租户已告知家长。
  3. 每个租户默认关闭，在「系统设置」里由店主打开，打开时显示上面的说明。
  4. 措辞由 Lee 定，必要时请律师看。

## 五 · 费用估算

假设一条跟进消息：输入约 1,500 token，输出约 300 token。一份评语初稿：输入约 4,000 token，输出约 400 token。没有算缓存折扣。这些 token 数是推断，没有实测。

| 模型 | 输入 / 输出（每百万 token） | 一条跟进消息 | 一份评语 | 每月 200 条消息 + 50 份评语 |
|---|---|---|---|---|
| Opus 5.5 | $4 / $20 | 约 $0.012 | 约 $0.024 | 约 $3.6 |
| Sonnet 5.5 | $2 / $10 | 约 $0.006 | 约 $0.012 | 约 $1.8 |
| Haiku 5.5 | $0.10 / $0.50 | 约 $0.0003 | 约 $0.0006 | 约 $0.09 |

即使用最贵的模型，一个活跃租户一个月也只有几美元。所以「谁付」更像是产品决定，而不是成本问题。

## 七 · 风险

| 风险 | 处理 |
|---|---|
| 草稿里编了一个数字 | 只给事实、`missing` 字段、界面逐项对照、人工确认 |
| 员工不看就发 | 界面把对照结果放在发送按钮旁边；发送永远是员工自己的动作 |
| API 不可用或变慢 | 20 秒超时；失败照常手写，不影响任何流程 |
| 费用失控 | 工作区月度上限 + 每租户起草次数上限 |
| 家长信息外流 | 只给最少的事实；不保存内容；租户自己选择打开 |
| 语气不合租户 | 租户写一段风格说明；评测里专门检查语气 |
