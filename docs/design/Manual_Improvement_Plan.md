# P0 · 手册说的和产品不是同一件事

## P0-1 配色系统的说法已经作废（**唯一一处「主动说错」**）

手册第 125 / 217 / 252 行说：

> 「系统共八套主题，每套都有明暗两版。」
> 「八套主题及其明暗模式合计 45 个值。」

v8.5.x 起真正的模型是**一套配色 + 自由强调色**：8 张精选卡是**起点**，不是全集；老板可以直接开取色器、**从 Logo 取色**，系统只取色相、自己重新解出明度与饱和度。

手册里 `自定义` / `取色` / `Logo` 出现 **0 次**。

**为什么这条排第一**：其余问题是「查不到」，这一条是「查到了，是错的」。一个老板读完会以为自己只能在八张卡里选，而**「用我自己的品牌色」正是他最想做的第一件事**。

**怎么改**：把「八套主题」改写成「八个起点 + 一个自己的颜色」，并说明系统只接受色相、明度饱和度由它重解（所以荧光色 Logo 出不来难看的站）。顺带写上：撞到状态色（红黄绿蓝）时系统会挪开并告诉你。

估时 **1 小时**。

## P0-2 公开课表 + 免注册约课：完全没写（v8.9.0 / v8.10.0）

手册有**一整章「家长这一侧」**，而这是 v8.5 之后唯一一个**家长会直接接触**的新功能。现在的状况是：家长照着手册找不到课表，老板照着手册不知道有这个开关。

要写的：

- 它是**独立页面** `/<slug>/timetable`，从门户导航进；
- **排了课 ≠ 对外招生** —— 逐条勾选，默认不展示（这一条最需要解释，否则老板会以为开关坏了）；
- 展示周数**同时就是约课的时间窗**（故意只有一个数字）；
- 余位三态：绿「还有 N 位」/ 琥珀「快满了」/ **灰「已满 · 可加候补」**（满了不是红色 —— 卖完是成绩）；
- 约课**不占座**，容量在批准那一刻才复核；
- 家长**不用注册**，姓名 + 手机号；重复提交返回「已经收到了」。

估时 **3 小时**（含中英双语）。

## P0-3 工作室作品 Selected Work：完全没写（v8.6.0 / v8.7.0）

**定价页正在按它卖钱**（starter 15 / studio 60 / growth 150 件），手册里这个功能不存在。

一个正在比较套餐的老板，会在手册里找不到他多付的那笔钱买到了什么。

# ⚠️ 一个要你拍板的设计问题（不是文档能解决的）

**前台（Front Desk）能看见约课申请，但批不了。**

- `list_class_bookings` = 任何登录用户可读
- `review_class_booking` = **仅 Owner / Manager**
- 前台角色有 `registrations:write`（**能批报名**），但没有批约课的权限

也就是说：**处理来客咨询的正是前台，而约课是来客咨询的一种，他却只能看不能动。** CMS 里那两个按钮对他直接不显示。

三个选择：

1. **给前台批约课的权限** —— 与他已有的「批报名」对齐。我倾向这个：两件事在前台眼里是同一件事（有人想来上课）。
2. **保持现状**，并在前台手册里明确写「约课请转给店长」—— 如果你希望占座位这件事只有店长能决定。
3. 折中：前台可**婉拒**、只有店长能**批准** —— 我不建议，多一条规则要记，收益很小。

**这一条不定，前台手册就没法写准。**

# 一条要记住的机制

`docs/guides/` 曾经**在 v8.1.0 停了九个版本**，这件事写在 `capture_manual_shots.py` 的注释里，也是那套自动截图存在的原因。

现在版本号是自动断言的（`test_user_guides.py` 逼着每次发布都改），**但内容没有任何东西在盯**。这一轮的欠账正是这么来的：版本号一路涨到 v8.10.3，内容停在 v8.5。

值得考虑的一条断言：**新增一个 `website_profile` 的 `show_*` 开关时，线上手册里必须出现它的名字。** 和 `test_section_switches.py` 拦住「孤儿开关」是同一种做法 —— 那条测试已经证明它有效。
