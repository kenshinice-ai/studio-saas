# 主理人 / 工作室成果展示 — 方案

> **状态更正：**工作室/主理人作品、独立 `/<slug>/showcase`、分类、精选排序、
> 套餐公开额度和 Studio Admin 编辑器已在 v8.6.0–v9.8.10 落地。本文保留产品
> 取舍与同意边界，不再表示该能力缺失。

**手写文件。** 与 `Design_Constraints.md` 同级：那份写禁令，这份写这一个板块的决定。

---

## 0. 它要解决的问题

工作室官网现在能证明「学员画了什么」（作品墙，CMS 供数、经学员同意），
**不能证明「这家工作室自己有多强」**。

对一间画室、一间琴房、一个舞团来说，后者才是家长决定要不要来的那一眼。
主理人板块只有一张头像加一段自述——**是主张，不是证据**。

这是两件不同的事，不能合并进作品墙：

| | 学员作品墙 `#gallery` | 成果展示 `#showcase` |
|---|---|---|
| 内容来源 | 运营 CMS（员工录入） | Studio Admin（主理人自己策展） |
| 归属 | 学员的 | 工作室 / 主理人的 |
| 同意模型 | 需学员同意 | 自己的作品，无需 |
| 目的 | 「在这里能学成什么样」 | 「教你的人是什么水平」 |
| 数量 | 随教学不断增加 | 少而精；首页精选前 6 件，独立作品页按套餐公开并以 12 件分页 |

合并会让「作品」这个词在同一页上有两个意思，也会把商业作品集和学员练习摆
在同一个标题下面。**分开是这个方案的前提。**

---

## 1. 位置

```
hero → about（空间） → artist（主理人） → ★ showcase（成果） → courses → gallery（学员作品） → …
```

紧跟在主理人之后，且**必须在学员作品墙之前**。阅读顺序是有论证结构的：

> 这是我们的空间 → 这是教你的人 → **这是他的作品** → 这是课程 → 这是学员学成的样子

放到作品墙后面，等于先给证据再给主张；放到主理人前面，等于还不知道是谁的作品。

---

## 2. 视频：只存链接，且默认不请求第三方

用户要求「用 iframe 或类似形式以链接提供，减缓服务器压力」。照做，但要做对三件事。

**2.1 本站 CSP 现在会拦掉任何第三方 iframe。**
`server.py` 只声明了 `default-src 'self'`，没有 `frame-src`——按规范 `frame-src`
缺省回退到 `default-src`，**所以今天嵌入 YouTube 会被静默拦截**。
这和本轮的 Cormorant 字体是同一个坑：功能写了，策略拦了，没有任何报错。
所以本方案**必须**同时改 CSP，并在浏览器里实测确认，而不是读代码确认。

白名单三家，其余一律拒绝：

| 提供商 | 嵌入域名 |
|---|---|
| YouTube | `https://www.youtube-nocookie.com`（无 cookie 域） |
| Vimeo | `https://player.vimeo.com` |
| Bilibili | `https://player.bilibili.com` |

**2.2 服务端只存规范化后的 video id + provider，不存原始 URL 片段。**
绝不把租户输入的字符串直接拼进 `src`。解析 → 取 id → 用我们自己的模板生成
嵌入地址。这样即使输入里带了 `"><script>`，它也到不了 DOM。

**2.3 点击才加载（façade）。**
默认渲染的是**工作室自己上传的封面图 + 一个播放键**，点击后才把 iframe 插进去。

- 一个 YouTube 嵌入首屏就是 ~700KB 的第三方 JS。12 个格子里有 3 个视频，页面
  还没滚动就多两兆——**这比服务器压力更贵，因为付钱的是访客的手机**。
- 在访客表达意图之前，不向第三方发出任何请求（也就没有第三方 cookie）。
- 封面图走我们已有的媒体管线（额度、安全副本、metadata 剥离）。

没有封面图的视频，退化成一块中性底 + 播放键，**不是空白**（Design_Constraints §5 同理）。

## 3. 布局：黄金分割

产品里已经有 φ 阶梯（`ui-tokens.css`：`--ui-phi`、`--ui-golden-columns`、
间距 5·8·13·21·34·55·89）。**不新造数字。**

**桌面**——`--ui-golden-columns`（1.618fr : 1fr）：

```
┌───────────────────────────┬──────────────┐
│                           │   item 2     │
│         item 1            ├──────────────┤
│        （主作品）          │   item 3     │
└───────────────────────────┴──────────────┘
┌────────┬────────┬────────┐
│ item4  │ item5  │ item6  │   …其余等分三列
└────────┴────────┴────────┘
```

第一件作品拿走 61.8% 的宽度——**策展是有主次的，一排等大的格子没有主次**。

- 主格 `aspect-ratio: var(--ui-phi)`（1.618:1，横向）
- 副格 `aspect-ratio: 1`（两个正方形叠起来正好等高于主格）
- 其余 `aspect-ratio: 1`
- **所有格子都写 `aspect-ratio`**，图片到达前就占好位（CLS<0.1；
  ux-guidelines「Content Jumping」严重度 High）

**移动端**单列，主格降为 4:5（竖屏手里更适合看画）。

**1 / 2 / 3 件时不留空格**：少于 3 件就退化成单列或等分两列，不硬凑那个网格。

## 4. 数据模型

放在 `website_profile`，与 About 同一族——同一个校验函数、同一条
「后台必须回发每个字段」的测试（`test_the_admin_sends_every_field_the_server_stores`）。

```
show_showcase        bool，默认 false
showcase_label       {zh,en}   眉题
showcase_title       {zh,en}   标题
showcase_lead        {zh,en}   引导语
showcase_items       list，最多 500（健全上限；公开数量跟随套餐）：
    image_url        我们的媒体 URL（封面 / 作品图）
    title            {zh,en}
    caption          {zh,en}   媒介、尺寸、年份之类
    featured_rank    1..500 或 null；租户全局精选顺序，数字越小越靠前
    publication_state active | draft | archived
    video_provider   youtube | vimeo | bilibili | ""
    video_id         规范化后的 id，"" 表示纯图片
```

一条既没有 `image_url` 也没有 `video_id` 的记录会被丢弃——**空格子不是内容**。

---

缺少 `publication_state` 的旧记录按 `active` 兼容；未知状态按 `draft` 处理，避免
意外公开。`featured_rank` 是可选的租户全局排序：有效排名会在保存/读取时压缩为
连续的 1..N，未填写的作品保持原有顺序并排在已排名作品之后。公开接口只读取
`active`，先按排名排序、再按 `plans.showcase_limit` 截取；套餐降级不删除记录，
升级后可恢复可见。首页使用独立的 6 件预览请求，`/<slug>/showcase` 使用 C 方案
每页 12 件，分页大小不是套餐上限。

## 5. 后台：单独一个 tab

12 条 ×（图 + 双语标题 + 双语说明 + 视频链接）放不进「官网」标签页，
会把已经很长的那一页压垮。**新开一个 `作品展示` tab。**

每条一张卡：缩略图、上传、双语标题、双语说明、可选 `featured_rank`、公开状态、
视频链接、上移/下移/删除。`featured_rank` 是租户全局精选顺序；1..6 决定首页
预览，独立作品页和分类 URL 沿用同一顺序。未填写时沿用列表顺序（上移/下移仍是
备用顺序），因此新增的 rank 不会让原有作品丢失。新上传在当前套餐的 active
容量用尽后自动进入 `draft`，仍可保存和编辑。

视频链接框在失焦时立即校验并回显识别结果（「已识别：YouTube」/「无法识别
这个链接」），不要等到保存才报错（ux-guidelines：inline-validation）。

## 6. 交互边界

- **作品点击打开可访问的灯箱/lightbox。** 对话框使用原生 `dialog`，支持 Esc、
  上一幅/下一幅、键盘方向键、可见焦点和 `prefers-reduced-motion`；视频仍然只在
  点击后创建 iframe。页面首屏不预加载第三方视频。
- **不自动播放，不做轮播。** 策展页要让人停下来看，不是替人翻页。
- **不托管视频。** 视频一个字节都不存；图片继续受媒体存储额度约束。
- **不把分页大小当套餐额度。** 首页一次加载 6 件，独立页每次加载 12 件；套餐
  上限由 `plans.showcase_limit` 决定，分类筛选也不能绕过这个上限。
- **不创建第二套分类排序。** 分类页是同一租户全局 `featured_rank` 顺序的过滤视图，
  每个分类通过 `/<slug>/showcase?category=<id>` 分享。
- **不给这个板块新配色。** 用 `--bg`（作品墙是 `--bg2`），靠交替底色区分两个
  板块，不引入第三种颜色（Design_Constraints §1.2）。
