# PWE Studio 用户手册 — 载体决策与实施规划（2026-08-03）

版本基线 v8.2.20 · 示例租户 `lets-paint-showcase` · 本轮只做规划，不写实现。

---

## 1. 先说结论：网页为源，打印样式产出 PDF

**一个文档，两种交付。** 不是"网页和 PDF 各做一份"。

### 为什么不是 PDF 优先

这个项目已经被"同一个事实存在两份、然后各自漂移"咬过三次，都有记录：

| 事故 | 两份在哪 | 结果 |
|---|---|---|
| 定价额度 | 页面写死 vs `plans` 表 | Paradise 页至今仍写 1500 学员 / 100 GB，数据库是 1000 / 50 GB |
| 发布依据 | 文件名带版本号 `Release_Notes_v8.1.0.html` | 生产跑到 v8.2.11 时页面还停在 8.1.0，两个发布没人发现 |
| 套餐可见性 | "存在"即"对外销售" | A$1 测试套餐会直接出现在公开定价页 |

PDF 在构造上就是第二份拷贝：导出那一刻起，它与产品的距离只会变大。手册里
有大量随版本变化的内容（权限表、菜单名、截图、限额），发一次 PDF 就等于
承诺每次发版重导一次——而"每次发版都要手工做一遍"的步骤，正是这个项目
里最容易被跳过的那一类（发布依据卡在 8.1.0 就是这么来的）。

### 网页多出来的东西，是支持工作真正需要的

- **可深链**。客服回消息时发 `pwestudio.online/manual/#refunds`，比"手册第 34 页"有用。
- **可被搜到**。`/ui-ux-pro-max` 的文档模式把 "no search / poor navigation" 列为
  两大反模式；PDF 两样都占。
- **截图可替换**。HTML 里截图是 `<img>`，改一张不用重导整本。
- **白嫖现成基建**。`customer-resources/` 已有共享令牌样式、双语机制、
  服务端白名单，以及 `test_customer_resources_brand.py` 里那套"不许写死 hex /
  必须双语 / 必须有法律主体 / 不许留占位符"的检查——新页面落进去当天就被覆盖。
- **浅色深色跟随系统**，和 v8.2.20 官网一致。PDF 只有一种。

### PDF 真正赢的场景，用打印样式接住

签约时交付一份、离线看、前台打印贴墙。做法：同一份 HTML 里写 `@media print`
（展开所有折叠、去掉导航与搜索、链接后追加 URL、分页断点、深色转纸面），页
内放一个「打印 / 存为 PDF」按钮。**源只有一个。**

> 这不是"用网页糊弄过去"。这是本项目刚在 v8.2.20 用过的同一条原则：双语写在
> 一个文件里、服务端拆成两份交付，而不是维护两份文件。

## 2. 内容不是从零写 —— `docs/guides/` 已经有 1,327 行

现状盘点（这是本轮最重要的发现）：

| 文件 | 行数 | 状态 |
|---|---|---|
| `docs/guides/README.md` | 111 | 五界面表、角色表、**后端强制权限矩阵**、通用概念、快速索引 |
| `Studio_Owner_Guide.md` | 278 | 品牌工作台、8 套主题、隐私声明版本、Owner 专属 |
| `CMS_Manager_Guide.md` | 238 | 工作台/排课/档案/审批/充值/访问码/日志/统计/设置 |
| `Super_Admin_Guide.md` | 238 | 租户、套餐、生命周期、支持模式、备份 |
| `Front_Desk_Staff_Guide.md` | 175 | 审批、建档、充值、访问码、疑似重复 |
| `Student_Parent_Guide.md` | 167 | 访问码自助查询、作品授权与撤回 |
| `Teacher_Guide.md` | 120 | 当日排课、签到、作品集 |

内容质量高且与后端权限一致，但**基线是 v8.1.0（2026-07-29）**，落后 v8.2.3–
v8.2.20 的全部改动：操作日志补全、媒体上传修复、配色体系重做、归档/删除、
数据保留、控制台计数器变筛选器、套餐发布开关、官网重做与语言拆分。

**所以手册是"设计 + 截图 + 交付 + 一次内容刷新"，不是"从零写作"。**
`docs/guides/` 继续作为内容源（工程侧可 diff、可 review），网页是它的成品面。

### 与现有 FAQ 的关系：不是同一个 FAQ

`customer-resources/FAQ.html` 现在是**采购/信任向**的（部署在哪、有没有备份、
恢复演练过没有、有没有 MFA、有没有 SLA）。手册要的是**操作向**的（怎么退费、
访问码丢了怎么办、家长为什么看不到作品）。两者不冲突，但必须互相指路，
否则读者会落错页——**手册不复制信任向 FAQ，只链过去。**

## 3. 结构（按运营者的一天排，不按菜单排）

```
0  开始之前          五个界面一张图 · 角色与权限边界 · 三个必须先懂的概念
                     （课时 vs 套餐 · 访问码 · 草稿 vs 发布）
1  第一天:上线       Studio Admin — Logo、主题、双语文案、报名问题
                     草稿 → 发布 → 版本回滚
2  招生              Register 二维码 · Portal 报名 · 待审核 · 疑似重复 · 隐私同意
3  日常              课程安排 · 调整 · 签到扣课时 · 余额不足当场拦截 · 日历导出
4  钱                充值 · 退费(权限边界) · 课时账本不可篡改 · 操作日志复核
5  作品              上传 · 默认私密 · 监护人同意 · 分享链接 1–90 天 · 撤回
6  家长侧            学员专区怎么用 · 访问码怎么发怎么换
7  团队              五级权限 · 前台能收费不能退费 · 谁能看统计
8  经营              统计与导出（Owner / Manager）
9  平台方会做什么     支持模式必须留痕 · 平台不读学员资料 · 审计
10 求助              支持渠道 · 边界 · 导入模版 · 出问题先看哪三样
11 操作 FAQ          ← 采购/信任向 FAQ 链到 customer-resources/FAQ.html
```

每章固定三段式：**这一步要做什么 → 截图 + 编号标注 → 会踩的坑**。
"会踩的坑"用产品真实行为写（例：余额不足是签到当场拦截，不是月底才发现）。

## 4. 设计 —— 沿用 v8.2.20 的令牌，φ 用在它真正管用的地方

不新造设计系统。直接继承官网那一套：`--phi`、φ^(k/2) 字阶、Fibonacci 间距、
Family Navy / Family Amber、五个 surface token + `--accent` 的浅深色换皮。

φ 的用法要克制（Brand_Identity 已写明"黄金分割是生成器，不是装饰"）：

| 用在哪 | 怎么用 |
|---|---|
| 正文栏宽 | `--measure: 61.8ch` —— 和 UX 规则的 65–75 字符一致，不是硬凑 |
| 纵向节奏 | 章 / 节 / 段间距走 Fibonacci `89 / 55 / 34 / 21` |
| 字阶 | 已有的 `--f-*`，标题到正文的跨度就是 φ 的幂 |
| 截图画幅 | 形状自由处用 `aspect-ratio: var(--phi)` |
| 分栏 | **不**把侧栏做成 38.2% —— 那会得到一个过宽的目录栏。侧栏按内容定宽，φ 留给正文测量与节奏 |

> 明确不做的事：为了"看起来像黄金分割"把导航栏拉宽。φ 用错地方就是装饰，
> 这条规范里写死了。

**截图呈现**：沿用家族已有的 `.ui-shot` 语言（navy-2 面板 + 三个圆点的窗口条），
截图外面套这个框。标注用**琥珀圆圈编号叠在图上，编号是 DOM 里的真文字不是烧进
图片的像素**——这样它能翻译、能被读屏读出、能随主题变色，下方配同号说明列表。

**长文导航**：粘性目录（`scroll-margin-top` 补偿，官网已有）、平滑滚动、
当前章高亮、页内搜索框（文档模式的第一反模式就是没有搜索）。宽表格套
`overflow-x: auto`，手机端权限矩阵转卡片。

## 5. 截图：真环境、真数据、可复制

- **来源**：本地实例 + `lets-paint-showcase` 演示租户。该租户本就是**合成数据**
  （虚构记录，从不使用客户数据），这正是它存在的理由——手册截图不会泄露任何真实学员。
- **可复现**：写一个 `docs/design/manual_shots.md` 记录每张图的路径、登录角色、
  视口尺寸、以及页面需要处于什么状态，下次发版照着重拍即可。
- **规格**：桌面 1440×900；签到 / 课程安排 另拍 390×844 手机版。
  WebP、显式 `width/height`（防 CLS）、`loading="lazy"`、有意义的 `alt`。
- **主题约定**：统一用演示租户默认主题的**浅色**，并在手册开头明说
  "你的工作室如果换了主题，颜色会不同，位置一致"。产品有 8 套主题 × 明暗，
  不说清楚会让读者以为自己装错了。
- **体积预算**：约 30 张 ≈ 2–3.5 MB。当前 `backend/frontend/assets/` 只有 760 KB，
  这是 4 倍增量，所以放 `/assets/manual/` 并全部懒加载（首屏只拉 3–4 张）。
  ⚠️ v8.2.18 的教训：9.2 MB 演示种子图曾躺在公开 `/assets/` 下无人引用 —— 手册
  截图是**故意公开**的，但要有预算、要被引用、要进 `.dockerignore` 的考量。

## 6. 交付形态与地址

- 落在 `customer-resources/` 家族里，继承共享样式与那套 brand 测试。
- **建议按 v8.2.20 的规矩拆语言**：`/manual/`（英）+ `/zh/manual/`（中），
  `apply_language` 已经写好，路由约 10 行。手册是这批页面里最可能被外部链接和
  搜索的一页，值得从第一天就一 URL 一语言；另外四页（FAQ/隐私/支持/条款）
  作为后续批次跟上。
- 入口：官网页脚「资料」区 + `#contact` 附近 + CMS 内的帮助入口（后续）。
