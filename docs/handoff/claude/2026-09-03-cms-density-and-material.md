## 排课页阶段二：理由不是版面

版面收益是边际的（实测净 −83px，方案预测 60–110px）。真正的理由是角色：
固定课表的增删改在 `@tenant_admin_required` 后面，一对一面板的 `canWrite` 是
`canWriteScheduling`。对 teacher 与助教，「排课设置」整半边都是按不动的东西 ——
放在页尾是「不挡路」，放进另一个标签才是「与我无关」。**实测可见按钮 55 → 26。**

共享上下文（日期导航、周视图、当日概览条）留在标签条之上，且整块留在
`.cms-roster-planner` 里没有拆散 —— 那张卡声明了 `container: roster-planner /
inline-size`，窄屏日期栏的栅格由 `@container` 规则给；把日期导航挪出这张卡，
那条规则会静默失效。

## 门禁自己抓到的两件事

把 8 个 CMS 页面加进 `ui_matrix.py` 之后，**第一次运行就失败**：工作台六个
38px、通知中心两个 32px 的触控区。而仓库里本来就有一条守这个的测试：

```python
assert "min-h-[36px]" not in source
assert "min-h-[40px]" not in source
assert "min-w-[40px]" not in source
```

一份**只列了三个字面量的黑名单** —— 也就是「上次有人看的时候恰好存在的那几个值」。
38 和 32 从它旁边走过去了。已改成规则（变异验证：放一个 40px 回去会失败）。

其中两个 32px 更值得记：它们头上的注释写着「Icon stays compact; the shared
aria-label rule expands its hit box to 44px」，而那个类正在压过那条规则 ——
Tailwind 工具类特指度 (0,1,0) > shell 的 `button { min-height: … }` (0,0,1)。
**代码与它自己的注释相反。**

## 材质：CSS 全对，效果为零

深色带的纸纹第一版：混合模式对、不透明度对、图片能取到，**实测渲染标准差
0.000 —— 完全平坦**。源图标准差只有 2.71/255（噪点做窄了又高斯模糊掉），
soft-light 在近黑底上本就压缩，8% 之后落差低于一个 8 位色阶。

一个不可能返回零的测量不是测量。

## 偏离方案的三处

1. **同日签到没有加第二次点击。** 方案写的是「行内两段式确认」，实测发现同日
   签到现在**根本没有对话框**，而且行内就有撤销。给前台最高频的动作加一次点击，
   是花钱买不到东西。真正该修的是那个用操作系统对话框的未来日期守卫。
2. **课程水印用真实 `<span aria-hidden>` 而不是 `::before` + `attr()`。**
   伪元素的 `content` 会被读屏念出来，而分类文字在 `.cage` 里已经有一份。
   方案的本意是「用 DOM 里已有的数据做装饰」，不是非要用 `attr()`。
3. **`stats` 不做分段。** 用本文档自己 §6 的规则否掉的：它是阅读页（全页只有
   5 个按钮），而规则写着「不要动 `logs` 的总高，报表长是它该有的样子」。
   「首屏外的块数」本身不是缺陷指标。
