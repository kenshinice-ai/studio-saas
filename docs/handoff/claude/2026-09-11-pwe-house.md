# 2026-09-11 · PWE 房子上线的前置：产品首页搬到 /studio（v10.18.0，未发布）

> 状态：**源码候选，分支 `release/10.18.0-pwe-house`，未推送、未打包、未部署。**
> 第 6–9 步由发布人执行。本文是 runbook 第 3 步的 prepared ledger。

## 为什么

公司的新「房子」网站（PWE · 天域）要接管 `pwestudio.online` 的根。上线后 nginx 会在
边缘直接以静态文件回答 `/`、`/zh/`、`/production/`、`/work/`、`/tools/`、`/labs/`、
`/about/`、`/services/`、`/contact/`、`/zh/ai/`、`/_pwe/`、`/llms.txt`、
`/sitemap-pwe.xml`、`/404.html`，并把 `/studio` 反代到本应用。所以在那之前，本应用
必须做到四件事：

1. 自己拥有 `/studio`（否则 nginx 的 `/studio` 只是临时借道 `/`）；
2. 把房子的前缀设为保留 slug（否则可以建出一个 nginx 会吞掉的租户）；
3. 已安装的 PWA 不再以 `/` 为起点（否则打开的是别人的首页）；
4. 不再把 Paradise Production 称作母品牌（文字层面；本版不换任何图标/图片）。

## 部署前必查（STOP GATE，发布人）

1. **nginx 对 `/zh/` 只能精确匹配，不能前缀匹配。** 本应用所有中文页都在 `/zh/` 下：
   `/zh/studio/`、`/zh/pricing`、`/zh/manual/`、`/zh/customer-resources/*`。如果房子用
   `location ^~ /zh/` 整个接管，这些页面全部 404。应为 `location = /zh/`（房子中文首页）
   + `location ^~ /zh/ai/`，其余 `/zh/…` 落回 `location /` 反代到应用。
2. **核对生产 5 个租户的 slug 不在新的保留名单里。** `validate_tenant_slug` 对保留 slug
   返回 404，所以一个叫 `studio`/`tools`/`about`…的现存租户会在部署后立刻消失。本仓库
   里的 3 个入库租户（`lets-paint-studio`、`lets-paint-showcase`、`music-studio-showcase`）
   已核对无冲突；另外 2 个只在生产数据库里，需要 `SELECT slug FROM tenants` 或看
   tenants 卷目录确认。
3. `/studio` 的反代不必改写成 `/`：本应用已自己路由 `/studio`。`/studio/llms.txt`、
   `/studio/` 会经 `location /` 兜底到应用，不需要额外 location。
4. 部署后 `curl -s https://pwestudio.online/manifest.json | jq .start_url` 应为
   `/platform-admin`；`/lets-paint-showcase/cms` 的 HTML 里应看到
   `href="/lets-paint-showcase/manifest-cms.json"`；`/robots.txt` 两行 `Sitemap:`。
5. deep health `workspaces.stale` 仍应为 0（entrypoint 会重生成工作区）。
