# PWE Studio v10.6.2 — 登记收款付错了发票

> Lee 在 INV-0007（$25）上点「登记收款」，屏幕上什么都没变，于是又点了几次。
> 每一次都成功了 —— 只是钱付到了**别的、更老的发票**上。查库：INV-0002 从
> part_paid 变成 paid、INV-0003 的已付从 4500 涨到 28000、还多出一张 INV-0008，
> 而 INV-0007 分文未动。总共动了 $2,280。
>
> `auto_allocate` 按 oldest-first 分配，**那本身是对的**，也是账房和家长都预期的。
> 错的是从**某一张发票的详情面板**发起的收款没有说明这笔钱是哪张单的：
> `POST /billing/payments` 收了 `invoiceId` 却直接丢掉。
>
> 这条我在体检里记过，标题是「两个静默丢弃」，归在 P1「接口一致性」里 ——
> **我把它当成了洁癖问题**。它不是。一个被接受又被忽略的字段，
> 在钱的接口上就是一笔付错地方的款子，而且不报错、不留痕、界面看起来像没反应。
>
> 修法：`auto_allocate` 接受 `prefer_invoice_id`，把它排到 oldest-first 的前面；
> 多余的钱仍然按最老欠款走，因为超付仍然是家长的钱。前端把当前发票的 id 带上。

## 另外两处

- **发票明细里「应付」「余额」显示为空**。数字一直在响应里（实测 total 2500 /
  balance 2500）。表格写的是 `w-full`，于是在窄详情栏里五列被压到接近零宽，
  而父容器的 `overflow-x-auto` 因为表格永远不会超出容器所以从不触发。
  给表格一个最小宽度，那个类才开始起作用。
- **「追加新授权记录」还是绿的**。v10.6.0 只改了未记录分支的「记录授权」，
  漏了已授权分支的这一个 —— 它同样是动作不是状态。改 accent。
