## 基线统一后，为什么调整执行顺序

10.6.3 已经证明“能构建、能运行、线上健康”，下一轮最值得优先解决的不是继续扩大
功能面，而是把**钱的正确性、产品承诺与可重复验收**锁住：

1. v10.6.2 的指定发票优先分配和 v10.6.3 的收款/退款事件是高风险修复，但对应提交没有新增回归测试；
2. Xero 已有开关、队列、映射与演示数据，但仓库中没有真实 OAuth/出站传输/任务消费证据；部分客户文档却写成已经可以直连；
3. CMS 仍承诺“周期账单会自动生成草稿”，而当前没有这个能力；
4. API、数据库和路线图文档分别停在旧版本/旧迁移，与 10.6.3 的真实合同不一致；
5. 完整门禁依赖被忽略的 `.agents` 镜像，干净检出时品牌合同测试不是自包含的。

因此最优路径是先建立不会倒退的护栏，再校正文案与合同，最后才增加新能力。

## 下一轮执行清单

### P0-01 钱款正确性护栏（建议下一个补丁版 v10.6.4）

- [ ] 为 `prefer_invoice_id` 增加回归测试：从发票详情登记的金额先付目标发票，超出部分才按 oldest-first 分配。
- [ ] 覆盖 `issued → part_paid → paid → refunded` 事件链，断言事件金额、事后余额、租户隔离和退款边界。
- [ ] 对写接口实行明确字段合同：支持的字段落实行为；不支持的字段返回 4xx，不再接受后静默丢弃；先覆盖 `invoiceId` 与 `dueDate`。
- [ ] 修正品牌合同测试，使其读取 Git 跟踪的 `.claude/skills` 权威源，而不是依赖被忽略的 `.agents` 运行时镜像。
- [ ] 在干净检出和两个 release archive 上各跑一次最小启动/合同检查。

**验收：**上述测试在修复前能复现旧缺陷、修复后稳定通过；跨租户 ID 被拒绝；完整 PostgreSQL 门禁通过；无数据迁移和既有账务语义漂移。

### P0-02 Xero 产品真相闭环

- [ ] 先把 Xero 定位统一为“预接入 / Preview”：在真实 OAuth、出站传输和可观测任务消费完成前，不再写“已直连”“自动同步”或“一键推送已生效”。
- [ ] 对齐 `Integration_Boundaries.md`、FAQ、Demo Runbook、客户 Release Notes 和界面开关说明；演示连接必须明确标记为合成数据。
- [ ] 将真正的 Xero transport 单独立项：OAuth 生命周期、幂等、重试/死信、速率限制、租户凭据隔离、审计与断连恢复分别验收。

**验收：**代码、界面、销售/客户文档对“当前能做什么”说法一致；没有网络调用证据时，任何表面状态都不能被解释为已同步。

### P0-03 删除不存在的周期账单承诺

- [ ] 立即替换 CMS 中“周期账单会自动生成草稿”的中英文文案，说明当前需要人工创建。
- [ ] 同步修改源文件、i18n 源与生成 bundle，不手改生成物形成漂移。

**验收：**全仓搜索不再出现自动生成草稿的承诺；中英文空状态一致；bundle 生成检查通过。

### P1-01 当前合同文档化

- [ ] 将 `docs/API.md` 更新到实际 v10 路由和钱款接口，并明确鉴权、租户范围、错误码、幂等与不接受字段。
- [ ] 将 `docs/Database.md` 更新到 migration 0042，标出钱款、Xero、审计和 RLS 关键不变量。
- [ ] 重写 `docs/Development_Roadmap.md` 的当前状态：已交付、试运行、Preview、未开始分栏，不沿用旧 Phase 状态。
- [ ] 增加自动检查：文档声明的最新 migration、版本与代码不一致时失败。

### P1-02 最小但真实的浏览器发布门禁

- [ ] 用合成租户覆盖：指定发票收款、发票事件历史、退款、Studio Admin 发布、公共导航/深链、Platform support。
- [ ] 覆盖 375 / 768 / 1024 / 1440 px，代表性明暗主题与中英文；检查键盘焦点、横向溢出、控制台错误和状态持久化。
- [ ] 把“HTTP 200”与“交互验收”分开记录；失败时保留页面、步骤、截图/日志与数据前后状态。

### P1-03 周期账单草稿（仅在产品确认后实施）

- [ ] 只生成可预览草稿，要求人工确认开具；不自动发送、不自动扣款。
- [ ] 运行必须幂等、可重跑、可审计，并显示将影响的租户/家庭/金额与异常记录。
- [ ] 未知或不完整数据保留为待处理，不猜测、不静默跳过、不自动合并。

### P1-04 运维与账户保障

- [ ] 建立实例外加密备份、备份年龄告警、深健康/磁盘告警和定期恢复演练。
- [ ] 为 Platform/Studio 高权限账户设计并验证 MFA；不把普通租户登录改造与其混在同一批。

### P2（在 P0/P1 形成稳定证据后）

- [ ] 把运行时 Tailwind/CSS 生成迁到构建期，逐步收紧 CSP 中的 `unsafe-inline`，每步做视觉与交互回归。
- [ ] 规范 API 命名和字段合同；先加兼容/弃用层，再考虑破坏性统一。
- [ ] 只有在 `api_v1.py` 的多人维护或变更冲突成为可量化成本时，再按领域拆分。

## 本阶段明确不做

- 不因这次文档闭环重建或重新部署已经验证的 10.6.3 归档；那会制造同版本不同字节。
- 不在同一批同时做 Xero transport、周期账单和 API 大拆分。
- 不引入 Redis/数据库连接池来“提前优化”；当前租户绑定使用 `SET` 而非 `SET LOCAL`，连接池会先带来隔离风险。
- 不做整站框架重写、主题系统重写或演示数据自动重置计时器。
