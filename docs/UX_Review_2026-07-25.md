# StudioSaaS UI/UX·文案·逻辑审查清单

- **版本**：v7.3.1
- **日期**：2026-07-25
- **范围**：Portal（`tenant-template/index.html`）、Register（`tenant-template/register.html`）、CMS（`legacy-root/src/cms-app.jsx`）、Studio Admin（`backend/frontend/studio-admin.html`）、Super Admin（`super-admin.html`）
- **性质**：只做检查，不改代码。以下每条都给出了文件与行号定位。

---

## 0. 一句话结论

代码工程质量不差（蜜罐、consent 版本号、safe-area、reduce-motion、CSV 导出、审计日志都在），**但四个界面是四个不同的人在不同时间做的**：三套语言策略、两套设计系统、两套表单实现、两套术语体系。当前最大的风险不是缺功能，而是**同一个租户在不同页面之间看起来不像同一个产品**，以及**通用模板里写死了美术行业词汇**——而你的租户里已经有钢琴、舞蹈、游戏。

## P0 — 上线阻断级（影响可信度 / 有安全问题）

### P0-1　同一产品四个界面、三套语言策略

| 界面 | 语言 |
|---|---|
| Portal / Register | 中英双语，有切换 |
| CMS | **纯中文**，`data-en`/`T()` 出现 **0 次** |
| Studio Admin | **纯英文**外壳，但字段默认值/placeholder 是中文 |
| Super Admin | 纯英文 |

- 定位：`legacy-root/src/cms-app.jsx`（全文无 i18n 层）；`backend/frontend/studio-admin.html:1928,1930,1935,1937,1979,1981,2181,2182,3005`（英文 label + 中文 placeholder 混排）
- 影响：**同一个工作室主每天要同时用 CMS 和 Studio Admin**——他必须同时看得懂中文和英文。不会中文的店主用不了 CMS；不会英文的店主用不了 Studio Admin。这直接卡死可服务的客户范围。
- 建议：先定位——是「面向澳洲华人工作室」（那 Super Admin/Studio Admin 应中文优先）还是「面向英语市场」（那 CMS 必须补 EN）。选定后，把 CMS 的中文字符串抽成一个 `strings.js` 字典，先补 EN 一套；Studio Admin 的 placeholder 改成跟随界面语言。**不建议**四个界面各自实现一套 i18n。

### P0-2　占位文案已经发布到公网

- 定位：`tenant-template/index.html:286-289`（`主理人姓名` / `【占位文案】在这里介绍工作室的主理人……请将本段替换为真实介绍`）、`:302-305`（4 张通用课程卡）、`:318-321`（4 个空作品格）、`:349-352`（4 条静态 FAQ）
- 实测：**5 个租户的 `index.html` 全部包含**「主理人姓名」和「【占位文案】」。
- 影响：家长打开门户就能看到「请将本段替换为真实介绍」。这是最伤信任的一类问题。
- 建议：把「渲染占位」改成「无数据则隐藏 section」。品牌接口没返回 `principal.bio` 就不渲染主理人区；`/gallery` 空就不渲染作品墙（现在会显示 4 个空色块）；`/programs` 空就不渲染课程网格。宁可页面短一点。

### P0-3　通用模板里写死了美术行业词汇

- 定位：`tenant-template/index.html` 同一文件里「画室」出现 5 次（`:332,352,432,461,481`）、「工作室」6 次；`legacy-root/src/cms-app.jsx:835,1041,3557` 有 `artStyle` / `favArtist` 字段并在学员卡片上以 `🎨` 展示；`:3532` 续课话术带 `🎨`
- 实测：`tenants/lets-play-piano`、`dance-dance`、`lets-play-game` 三个租户的门户上都写着「画室发放的访问码」。
- 影响：钢琴/舞蹈/游戏租户的公开页面在自称画室。README 的定位是 art schools + music studios + tutoring + creative academies，模板却只服务其中一种。
- 建议：
  1. 术语抽成品牌变量：`{{VENUE_NOUN}}`（画室/琴行/教室/中心）、`{{WORK_NOUN}}`（作品/曲目/录像/项目），在 Studio Admin 里按行业预设选择。
  2. `artStyle`/`favArtist` 归入已有的 `legacyPreferenceKeys`，用 `registration_profile` 的自定义字段替代（这套机制已经有了）。

### P0-4　语言切换用 `innerHTML`，且品牌文案直接进 attribute → 存储型 XSS

- 定位：`tenant-template/index.html:534`（`e.setAttribute('data-zh', e.innerHTML)`）、`:538`（`e.innerHTML = e.getAttribute('data-en'|'data-zh')`）、`:549-567`（`setCopy` / `setLocalizedCopy` 把 `/brand` 返回的文案原样 `setAttribute`）
- 路径：Studio Admin 里可编辑 hero title / subtitle / CTA / FAQ → 存进 brand → Portal `setCopy` 写进 `data-en` → `setLang()` 用 `innerHTML` 渲染 → **脚本在访客浏览器执行**。
- 对照：`tenant-template/register.html:156-158` 用的是 `element.textContent = element.dataset[currentLanguage]`，**是安全的**。
- 建议：把 Portal 的 i18n 改成 register.html 的写法（`textContent` + `data-zh`/`data-en` 双属性预置），唯一需要 HTML 的隐私链接单独处理。

### P0-5　Portal 与 Register 是两套完全不同的设计系统

| | Portal | Register |
|---|---|---|
| 主色 | `--clay #A65A43` 陶土 | `--brand #2563eb` 蓝 |
| 背景 | `#F4F0E8` 纸质暖白 | `#f8fafc` 冷灰 |
| 字体 | Cormorant Garamond + Noto Serif SC | 系统字体栈 |
| 圆角 | `2px`（近直角） | `8px` |
| 字重 | 300/400/500 | 800/900 |

- 定位：`tenant-template/index.html:34-37` vs `tenant-template/register.html:15-24`
- 影响：家长在门户点「报名」跳到 `/register`，视觉上像跳到了另一家公司。品牌一致性直接崩，转化环节最不该出现这个断层。
- 建议：`ui-tokens.css` + `brand-system.css` 已经存在了，两个页面却各自又定义了一套 `:root`。统一到 token 层，让 Register 继承 Portal 的品牌变量。

## P1 — 显著影响转化与可用性

### P1-1　Portal 的报名表不是 `<form>`，且缺 `autocomplete`

- 定位：`tenant-template/index.html:379-415`
- 问题：
  - 没有 `<form>` 元素 → **手机键盘上按「前往/完成」不会提交**，`required` 属性形同虚设，没有原生校验。
  - `j-name`/`j-last`/`j-phone`/`j-email` **全部没有 `autocomplete`**（只有 `j-publication-by` 有）→ 移动端自动填充失效，每个字段都要手打。
- 对照：`register.html:102-108` 是标准 `<form>` + `autocomplete="given-name|family-name|tel|email"`，做对了。
- 影响：这是转化漏斗最后一步的直接损耗。
- 建议：把 Portal 的 join 表单换成 register.html 的实现，或**直接把两处合并成一个共享组件**（见 P1-2）。

### P1-2　同一个报名流程有两套实现，且已经跑偏

- 定位：`tenant-template/index.html:767-802`（`submitJoin`）vs `tenant-template/register.html:258-313`（`submit` handler）
- 已经产生的差异：`<form>` 有无、`autocomplete` 有无、隐私说明有无链接、成功页文案不同、`source` 值不同（`portal` vs `standalone_register`）、`privacyNoticeVersion` 两处硬编码。
- 建议：抽到 `assets/public-register.js`（这个文件已经存在，只承担了自定义字段渲染）。让它同时负责校验、提交、成功态。

### P1-3　Register 页收集了隐私同意，却没有隐私说明可看

- 定位：`register.html:112`（勾选框文案「我同意工作室仅将这些资料用于联系与课程管理。」**无链接**）、`:289-290`（提交时带 `privacyConsent:true, privacyNoticeVersion:'2026-07-12'`）
- 对照：Portal `index.html:401` 的中文版有跳转隐私页的链接，但**英文版 `data-en` 里没有链接**，且写的是「See the Privacy note below」——页面下方并没有。
- 影响：以一个版本号记录了用户对某份隐私声明的同意，但用户在这个界面上根本看不到那份声明。合规上站不住。
- 建议：Register 页加隐私说明入口（弹层或新窗口）；Portal 英文版补链接；`privacyNoticeVersion` 从接口下发而不是两处硬编码。

### P1-4　`hero-bold` 主题下主 CTA 按钮不可见

- 定位：`tenant-template/index.html:81`（`body.hero-bold .hero{background:var(--ink)}`）+ `:71`（`.btn-fill{background:var(--ink)}`）
- 问题：租户在 Studio Admin 里选「bold」hero 样式后，深色按钮落在深色背景上，**主 CTA 消失**。
- 建议：`body.hero-bold .btn-fill` 反转为 `background:var(--bg);color:var(--ink)`，或统一用 `--brand-accent`。

### P1-5　正文字色对比度不达 WCAG AA

实测（已用相对亮度算过）：

| 组合 | 比值 | 结论 |
|---|---|---|
| `--muted #8B8477` on `--bg #F4F0E8` | **3.26** | 不达标（需 4.5） |
| `--muted #8B8477` on `--bg2 #ECE6DB` | **2.98** | 不达标 |
| `--ink2 #4A473F` on `--bg` | 8.16 | 达标 |

- 受影响：`.course p`（课程说明，13.5px）、`.form-note`（同意条款说明）、`.info-row .k`、`.tile .cap`、`.foot .cp`
- 定位：`tenant-template/index.html:36`
- 建议：`--muted` 调深到约 `#6E675A`（对 `--bg` 约 4.6:1）。

### P1-6　`/programs`、`/gallery`、FAQ 的动态内容不跟随语言切换

- 定位：`tenant-template/index.html:533`（`i18nEls` 在解析时一次性快照）；`:712-717`（FAQ 动态插入）、`:743-755`（课程卡动态插入）、`:898-906`（作品墙）
- 问题：这些节点是 fetch 回来后才创建的，不在 `i18nEls` 里，**点 EN 永远不变**。而且 API 的 FAQ 只有 `item.question`/`item.answer` 单语字段，本来也存不下双语。
- 建议：`setLang()` 改成每次实时 `querySelectorAll('[data-en]')`；`/brand` 的 `faq_items` 扩成 `{question:{zh,en}, answer:{zh,en}}`。

### P1-7　按内容里有没有汉字来猜语言

- 定位：`tenant-template/index.html:557`（`var language=/[㐀-鿿]/.test(value)?'zh':'en'`）
- 问题：租户只填了中文文案 → `data-en` 保持模板默认的英文占位 → **英文访客看到的是模板样板文，不是这家工作室的真实文案**；反之亦然。
- 建议：Studio Admin 已经有 `localizedCopy` 的 `{zh,en}` 结构（见 `studio-admin.html:2181-2182`），全面走这条路，废掉 `setCopy` 的猜测分支；某一语言缺失时回退到另一语言的真实内容，而不是回退到模板占位。

### P1-8　续课提醒话术把租户名写死成 "Studio"

- 定位：`legacy-root/src/cms-app.jsx:3532`
  ```
  `${s.name} 您好～您在 Studio 的剩余课时为 ${s.balance} 节，……欢迎随时联系老师续课哦 🎨`
  ```
- 影响：这段文字是给店员**一键复制粘贴到微信发给家长的**。家长收到的消息里字面写着 "Studio"，末尾还有个跟钢琴/舞蹈无关的 🎨。
- 建议：换成 `${tenantDisplayName}`，emoji 去掉或按行业配置；话术本身做成 Studio Admin 里可编辑的模板。

### P1-9　主理人头像路径没有按租户隔离

- 定位：`tenant-template/index.html:283`（`src="/site/principal.jpg"`）
- 问题：根路径绝对地址，所有租户指向同一张图。要么 404（现在靠 `onerror` 藏起来），要么串图。
- 建议：改成 `/{{TENANT_SLUG}}/site/principal.jpg` 或完全走 `principal.image_url`。

### P1-10　`tenants/lets-paint-studio` 已经从模板分叉

- 实测行数：模板 956，`dance-dance`/`lets-play-game`/`lets-play-piano`/`ruby-studio` 都是 956，**`lets-paint-studio` 是 1072**（含图片轮播等模板里没有的功能，且 `<title>` 已被手工改成 `Let's Paint Studio | Melbourne Art Studio & Painting Classes`）。
- 影响：旗舰租户不再从模板生成。以上所有模板修复都到不了它身上；反过来它上面的改进也回流不到模板。
- 建议：决定方向——要么把轮播/SEO 能力回收进模板 + 品牌字段，要么明确把它标记为「手工维护，不再同步」并写进 README。现在是介于两者之间的最坏状态。

### P1-11　Google Fonts 阻塞加载

- 定位：`tenant-template/index.html:25-27`（Cormorant Garamond + Noto Serif SC + Noto Sans SC，三个家族多个字重）
- 问题：中文优先的产品从 `fonts.googleapis.com` 拉字体；中国大陆访问会长时间挂起再 fallback。Noto Serif SC / Noto Sans SC 全量子集体积很大。
- 建议：自托管 + `unicode-range` 分片，或改用系统字体栈做中文正文、只对西文标题保留 Cormorant。

### P1-12　缺 `og:image`

- 定位：`tenant-template/index.html:10-12`（只有 `og:type`/`og:title`/`og:description`）
- 影响：家长把链接分享到微信/WhatsApp 时没有缩略图，点击率明显更低。对以口碑转介为主的获客渠道是实打实的损失。
- 建议：`og:image` 指向租户 hero 图或 logo，加 `og:image:width/height` 和 `twitter:card`。

## P2 — 打磨与一致性

### P2-1　导航靠 `onclick` 而非真链接，且 SPA 视图不改 URL

- 定位：`tenant-template/index.html:260,261,263,302-305,323,335-337,500-504`（大量 `<a onclick="go(...)">` 无 `href`）；`:616-625`（`go()` 不改 `location`）
- 后果：键盘 Tab 到不了、屏幕阅读器识别不出可点击、右键「新标签页打开」失效、**无法直接给出「报名页」链接投放广告**、浏览器后退键直接离开站点。
- 建议：改成 `<a href="#join">` + hash 路由，`go()` 同步 `history.pushState`。

### P2-2　顶部状态提示条被固定导航盖住

- 定位：`tenant-template/index.html:249`（`#surfaceStatus` 在 `<main>` 顶部，无 top 偏移）+ `:48`（`nav{position:fixed}`，高 74px）
- 后果：品牌/课程/作品墙加载失败时的黄色提示条渲染在导航底下，用户看不见。三个 `catch` 还共用这一个元素，互相覆盖，且从不消失。
- 建议：给它 `margin-top:74px` 或改成右下角 toast；每个来源独立提示并可关闭。

### P2-3　课程网格数量不是 4 的倍数时边框错乱

- 定位：`tenant-template/index.html:113-115`（`repeat(4,1fr)` + 只给 `:first-child` 加左边框）；`:743`（`programs.slice(0,8)`）
- 后果：返回 5/6/7 个课程时第二行边框缺失、右侧断线。
- 建议：改成每个 cell 都有 `border-left`，容器 `margin-left:-1px`；或用 `gap` + 卡片式边框。

### P2-4　学员专区的失败提示有两套不一致的措辞

- 定位：`tenant-template/index.html:461`（「无法验证这些资料。请核对三项信息，或联系画室更换访问码。」）vs `:827`（「无法验证这些资料，请核对后重试」）
- 另：`:826` 的 429 提示「尝试次数过多，请稍后再试」**没告诉用户要等多久**。
- 建议：统一一套文案；429 从响应头带上 `Retry-After` 并显示具体分钟数。

### P2-5　余额为负时提示文案是错的

- 定位：`tenant-template/index.html:850-852`
- 逻辑：只判断 `bal===0` 和 `bal<=2`。余额为负（欠课）会落进 `bal<=2` 分支，显示「课时即将用完，欢迎续课」——实际已经透支。
- 建议：补 `bal<0` 分支，文案改成「当前已透支 N 课时，请联系老师结算」。

### P2-6　访问码用了 `autocomplete="one-time-code"`

- 定位：`tenant-template/index.html:437`
- 问题：这是长期有效的 6 位码，不是短信验证码。iOS 会去抓短信里的验证码往里填，反而干扰。
- 建议：改成 `autocomplete="off"` 或 `current-password`。

### P2-7　CJK 排版：全大写 + 大字距 + 800/900 字重

- 定位：`tenant-template/index.html:175`（`.fld label{text-transform:uppercase;letter-spacing:.14em}`）、`register.html:44`（`letter-spacing:.08em;font-weight:800`）、`:51`（按钮 `font-weight:900`）
- 问题：`text-transform:uppercase` 对中文无效但字距会把汉字拉散；Noto Sans SC 只加载了 300/400/500，`font-weight:800/900` 会触发合成粗体（发虚、边缘毛糙）。
- 建议：中文语境下 `letter-spacing` 降到 `.02em` 以内；字重不超过实际加载的档位。

### P2-8　表单错误只有一条全局提示，没有字段级定位

- 定位：`tenant-template/index.html:772`、`register.html:173-178`
- 问题：10 个字段的表单，报错只显示一句话并滚到中间，用户还得自己找是哪一个。
- 建议：错误时给对应输入框加 `aria-invalid` + 红框，并 `focus()` 到第一个出错字段。

### P2-9　CMS 里 `window.alert` / `window.confirm` 与自研 `confirm()` 混用

- 定位：自研弹窗 `ConfirmDialog` 用了 20+ 次；但 `legacy-root/src/cms-app.jsx:345,356,457,460,470,471,476,477,478,1070` 仍用原生 `alert`/`confirm`
- 问题：同一个 App 里两种确认框样式，其中恢复备份这种**最危险的操作**（`:470-478`）反而用的是原生弹窗。
- 建议：统一到 `ConfirmDialog`，危险操作用 `danger` 变体 + 要求输入确认词。

### P2-10　全站用 emoji 当图标

- 定位：`cms-app.jsx:2439-2445`（导航 📊📅👥📋💰📜📈）、`:2997-3000`、`:3557`、`:3532`；`index.html:236`（`☰`）、`:449`（`⏭`）、`:401`（`🔒`）；`studio-admin.html:1765`（`🌐`）
- 问题：emoji 跨平台字形不一致（Windows/Android/macOS 差别很大）、无法跟随品牌色、屏幕阅读器会念出「电脑显示器」这类描述、也无法调粗细。
- 建议：换 Heroicons 或 Lucide 的内联 SVG（`currentColor`），一次性替换。这是 ui-ux-pro-max 交付前检查清单的第一条。

### P2-11　Studio Admin 的分段控件里同时有两个「选中」

- 定位：`backend/frontend/studio-admin.html:2054-2060`——`.device-tabs` 这一个容器里同时放了语言切换（中文/EN）和设备切换（Desktop/Mobile），**两个按钮同时带 `active`**。
- 后果：视觉上像是一个 4 选 1 的分段控件却有 2 个高亮，用户不知道点了会发生什么。
- 建议：拆成两个视觉上分开的 group，各自有标签。

### P2-12　CMS 内部术语不统一

| 概念 | 出现的说法 | 位置 |
|---|---|---|
| 学员 | 「学员档案」84 次 vs 首屏 KPI「**客户**总数」1 次 | `cms-app.jsx:3005` |
| 排课 | 「排课」21 次 vs 「排**班**」10 次（同一屏内：KPI 写「今日排班」，按钮写「今日排课」） | `:3007` vs `:2997` |

- 「课时」的英文尤其要注意：如果一节课可能扣 2 个 credit，`classes remaining` 就是错的，应为 `credits remaining`。

### P2-13　切换语言会清空已填的自定义字段

- 定位：`register.html:166`（`applyLanguage()` → `applyBrandContent()` → `renderFields()` 重建 `#customFields`）
- 后果：用户填到一半点了 EN，自定义字段的内容全没了。
- 建议：`renderFields` 前先收集当前值，重建后回填。

### P2-14　学员列表无分页/无虚拟化/无批量操作

- 定位：`cms-app.jsx:3539` 起（`sortedFiltered.map` 直接全量渲染卡片）
- 现状：超过 15 条时加了个「回到顶部」按钮，但没有分页。200+ 学员时一次渲染 200 张卡片。也没有多选，批量操作只有「低余额筛选下复制全部话术」一条。
- 建议：加分页或窗口化；加 checkbox 多选 + 批量归档/批量发提醒。

### P2-15　埋点覆盖不全

- 定位：`index.html:260-261` 只有 hero 两个 CTA 带 `data-analytics-event`；课程卡的「报名 →」（`:302-305`）、学员专区三张卡（`:335-337`）、导航 CTA（`:233`）、页脚都没埋。
- 后果：漏斗数据缺口，说不清哪个入口在带量。
- 建议：改成事件委托，凡是 `[data-analytics-label]` 的点击统一上报；补 `form_started` / `form_abandoned`。

## P3 — 可选优化

- **P3-1** `go()` 切换视图后不移动焦点（`index.html:616-625`），屏幕阅读器用户停在原地。建议 `focus()` 到新视图的 `<h2>`。
- **P3-2** 移动端菜单无 Esc 关闭、无点击外部关闭、无焦点陷阱（`index.html:572-577`）。
- **P3-3** `.langtog button` 高度约 30px，低于 44px 触控目标（`index.html:61`）；也缺 `aria-pressed`（Register 有，Portal 没有）。
- **P3-4** 品牌数据 fetch 返回前先渲染模板默认值，会看到一次内容闪变（`index.html:628` 起）。建议关键区块加骨架屏或 `visibility:hidden` 到数据落地。
- **P3-5** `body{overflow-x:hidden}`（`index.html:40`）是在掩盖横向溢出而不是修它。
- **P3-6** 提交成功文案「老师会尽快与您联系」（`index.html:418`）没有时间预期。改成「24 小时内」这类具体承诺可以显著减少重复提交和追问。
- **P3-7** 搜索框把 🔍 放进 `placeholder` 文本里（`cms-app.jsx:3504`），应该用图标装饰位。
- **P3-8** Portal 报名表「名字 *」必填在前、「姓 选填」在后（`index.html:381-382`），中文语境反直觉；且中文 label 配英文 placeholder（`First name`/`Last name`）。手机号 placeholder 写死 `04xx xxx xxx`（澳洲格式）但界面是中文优先。
- **P3-9** `LocalBusiness` 结构化数据在无地址/电话时会输出空字符串字段（`index.html:702-706`）。
- **P3-10** 「商业洞察」（`cms-app.jsx:2445`）这个命名对小工作室店主偏重，「经营统计」更贴近实际内容。
